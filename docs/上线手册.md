# resume-ai-prod · 上线手册（RUNBOOK）

> 本手册把「代码已就绪」推进到「可点上线」。覆盖：启动服务端、验证、构建前端、配置、
> 本机重客户端、监控接入、上线前检查。
>
> ⚠️ **边界（诚实声明）**：以下均为 R1 技术动作。**部署到生产机器、提供真实招聘平台账号/
> API 密钥、点击上线开关、PIPL 法定签署**仍属**用户独有物理动作**，本手册不伪造"已上线"——
> 真实凭据/签名需用户在本机完成。上线前请先过 `design/guardrails/pre-deploy-safety-checklist.md`。

---

## 1. 架构与组件

| 组件 | 形态 | 运行位置 | 说明 |
|------|------|----------|------|
| 服务端 API | `scaffold/src/server_main.py`（零依赖 stdlib http.server） | 单机器 / 小容器 | 25 契约端点 + `/healthz` + `/metrics`；护栏3 自动挂接 |
| 前端 | `frontend/`（Vue 3 + Element Plus + Vite） | 静态托管 | `npm run build` → `frontend/dist` |
| 本机重客户端 | `scaffold/src/local_agent.py`（浏览器自动化编排） | **用户本机** | 服务端不持凭据；适配器默认 MockAdapter，真实 Playwright 适配器由用户本机注入 |

设计定位：**重客户端（本机 Agent 跑浏览器自动化）+ 轻量服务端（API/LLM 匹配/通知/状态机）**，
服务端**不跑浏览器**、不持用户平台凭据（HLD §2.2）。

- Python **3.13**（服务端零依赖，仅标准库）

## 3. 启动服务端

### 方式 A · 直接运行（开发 / 验证）
```bash
cd <repo>
python scaffold/src/server_main.py
# 默认监听 0.0.0.0:8080（可用 PORT / HOST 环境变量覆盖）
```

### 方式 B · Docker 构建运行
```bash
cd <repo>
docker build -t resume-ai-prod:local .
docker run -p 8080:8080 --env-file .env resume-ai-prod:local
```

### 方式 C · docker compose（单容器，含健康检查）
```bash
cd <repo>
docker compose up --build -d
```

## 11. 阶段二：全栈 compose 真实部署（server-java + server-python + frontend）

> ⚠️ **实现说明**：本文档 §1–§10 描述的是**早期 MVP 桩** `scaffold/src/server_main.py`（零依赖契约桩，仅验证契约/监控/路由）。
> 经 DPIRA-BATCH-001（2026-08-19）实证，本仓库**生产部署目标**已演进为 `docker-compose.yml` 编排的多服务栈：
> **前端(nginx) → server-java(业务后端 :8080) → server-python(LLM 网关 :8000)**，后端经 JDBC 连 MySQL(`resume_ai`)、经 Redis 做幂等/缓存、经 RabbitMQ 派发投递任务。
> 以下步骤以 `docker-compose.yml` 为权威来源，并与 W1–W3 运行时实证一致。

### 11.1 拓扑（来自 docker-compose.yml）
```
前端(nginx :5173→80) --/api--> server-java(:8080)
                                  |--JDBC--> MySQL(resume_ai)
                                  |--Redis--> Redis(幂等/缓存)
                                  |--AMQP--> RabbitMQ(apply.task.queue)
                                  |--REST--> server-python(:8000, LLM 网关 + 本机 Agent 触发)
本机 Agent 不在容器内：服务端不持 Cookie/平台凭据，消费者经 AGENT_CALLBACK_BASE_URL 回调用户机器。
```

### 11.2 前置
- Docker + Docker Compose（守护进程可用；W1 已实测 MySQL 8.0.38、Redis 7、RabbitMQ 3.13 均可本地/容器运行）。
- 复制 `.env.example` → `.env`，至少填：
  - `DB_PASS`（MySQL root 密码，生产用强口令，非 root 账号更佳）
  - `INTERNAL_TOKEN`（**必须设置**，缺失→server-python fail-closed 拒绝全部内部调用，无后门）
  - `RESIMEAI_JWT_PRIVATE_KEY` / `RESIMEAI_JWT_PUBLIC_KEY`（**生产必须注入 PEM 成对密钥**；留空→启动生成临时 RSA-2048，仅开发，重启失效，WARN 日志）
  - `LLM_API_KEY`（可选；缺失→网关不可用→自动三级降级链兜底，防生产事故，不崩）
  - `AGENT_CALLBACK_BASE_URL`（默认 `http://host.docker.internal:9800`，容器内经 `host-gateway` 访问宿主机本机 Agent）

### 11.3 部署步骤
```bash
cp .env.example .env          # 补齐上述密钥
docker compose --env-file .env up -d --build
# 镜像：resume-ai-server-java:local / resume-ai-server-python:local / resume-ai-frontend:local
# server-java 启动即由 Flyway 自动跑 V1–V10 迁移（W1 实证：10 迁移全 success=1 / 25 表）
```

### 11.4 健康检查（go/no-go 闸门）
| 探针 | 命令 | 期望 |
|------|------|------|
| server-java | `curl -s http://localhost:8080/actuator/health` | `{"status":"UP"}` |
| server-python | `curl -s http://localhost:8000/healthz` | `200` |
| 前端 | `curl -s -o /dev/null -w "%{http_code}" http://localhost:5173/` | `200` |
| RS256 闭环 | `POST /auth/login`→取令牌→`GET /auth/users/me` 带令牌 | `200`；无令牌→`401` fail-closed |
| 内部令牌门 | `POST /internal/v1/ai/match` 无 `X-Internal-Token` | `401`；带正确令牌→进业务层 |

> W3 已全量实证上述五项（server-java RS256 真实签发 alg=RS256、user/me 200、fail-closed 401；server-python healthz 200、内部端点 401/带令牌 400）。

### 11.5 RS256 与 Agent 回调契约
- **RS256**：`JwtTokenSigner` 用注入私钥签发、`JwtVerifier` 用公钥验签；`SecurityConfig` 显式 `permitAll` + `JwtAuthFilter` 在过滤器层执行 fail-closed（非白名单路径无令牌一律 401，无 dev 兜底）。
- **Agent 回调**：投递任务经 RabbitMQ → `ApplyTaskConsumer` 消费 → 经 `AGENT_CALLBACK_BASE_URL` 调用户机器上的本机 Agent 执行浏览器自动化；服务端**永不持有平台 Cookie/凭据**（HLD §2.2 / ADR-002）。

### 11.6 已知缺口（go/no-go 前必读 · 诚实标注，不伪造"已闭环"）
- **F1（HIGH·跨服务缺口）**：`job` 读表从未被创建。`Job` 实体 `@TableName("job")`，`JobRepository`(MyBatis-Plus) 默认查 `FROM job`；V3 迁移注释声明"由 Python 采集器经 Alembic 创建"，但 **server-python 侧无 Alembic/建表代码**，compose 也无创建环节 → `resume_ai.job` 永不存在 → `GET /api/v1/jobs` 报 `Table 'resume_ai.job' doesn't exist`(500)。属 ADR-002 双语言异构下 Python 侧承诺**未交付**。当前 W3 实证下 jobs 读接口不可用；决策（Java 侧补迁移 vs Python 补 Alembic）待用户拍板，本手册不擅自静默补表。
- **B-1（MVP 认证）**：`UserService.login` 为占位实现（非空凭据即签发，未对 `t_user` 做密码哈希比对），上线前须替换为真实密码校验。
- **前端本地构建**：本机直接 `npm run build` 写 `dist` 时，vite 的 `emptyOutDir` 清理被**沙箱 safe-delete 钩子**拦截报错；改用外部 outDir 或容器构建不受影响（CI/容器无此钩子）。属环境 artifact，非代码缺陷。
