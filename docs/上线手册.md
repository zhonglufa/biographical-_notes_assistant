# resume-ai-prod · 上线手册（RUNBOOK）

> 本手册把「代码已就绪」推进到「可点上线」。覆盖：启动服务端、验证、构建前端、配置、
> 本机重客户端、监控接入、上线前检查。
>
> ⚠️ **边界（诚实声明）**：以下均为 R1 技术动作。**部署到生产机器、提供真实招聘平台账号/
> API 密钥、点击上线开关、PIPL 法定签署**仍属**用户独有物理动作**，本手册不伪造"已上线"——
> 真实凭据/签名需用户在本机完成。上线前请先过 `design/guardrails/pre-deploy-safety-checklist.md`。

---

## 1. 架构与组件

| 组件 | 形态 | 运行位置 | 说明 |
|------|------|----------|------|
| 服务端 API | `scaffold/src/server_main.py`（零依赖 stdlib http.server） | 单机器 / 小容器 | 25 契约端点 + `/healthz` + `/metrics`；护栏3 自动挂接 |
| 前端 | `frontend/`（Vue 3 + Element Plus + Vite） | 静态托管 | `npm run build` → `frontend/dist` |
| 本机重客户端 | `scaffold/src/local_agent.py`（浏览器自动化编排） | **用户本机** | 服务端不持凭据；适配器默认 MockAdapter，真实 Playwright 适配器由用户本机注入 |

设计定位：**重客户端（本机 Agent 跑浏览器自动化）+ 轻量服务端（API/LLM 匹配/通知/状态机）**，
服务端**不跑浏览器**、不持用户平台凭据（HLD §2.2）。

---

## 2. 前置依赖

- Python **3.13**（服务端零依赖，仅标准库）
- Node **18+**（前端构建）
- Docker **可选**（容器化部署）

---

## 3. 启动服务端

### 方式 A · 直接运行（开发 / 验证）
```bash
cd <repo>
python scaffold/src/server_main.py
# 默认监听 0.0.0.0:8080（可用 PORT / HOST 环境变量覆盖）
```

### 方式 B · Docker 构建运行
```bash
cd <repo>
docker build -t resume-ai-prod:local .
docker run -p 8080:8080 --env-file .env resume-ai-prod:local
```

### 方式 C · docker compose（单容器，含健康检查）
```bash
cd <repo>
docker compose up --build -d
```

## 4. 验证三端点

```bash
# 存活探针
curl -s http://localhost:8080/healthz
# -> {"status":"ok","endpoints":25}

# Prometheus 指标（护栏3 四指标 + 告警）
curl -s http://localhost:8080/metrics
# -> rat_apply_success_rate / rat_ban_rate / rat_error_rate / rat_llm_cost_cents / rat_alert

# 契约端点（按 A 编号路由；有效请求过契约 -> 200）
curl -s -XPOST http://localhost:8080/api/A01 \
  -H 'Content-Type: application/json' \
  -d '{"channel":"email","deviceId":"dev-001","email":"user@x.com","password":"secret123"}'
# 无效请求（缺字段 + additionalProperties:false）-> 422 fail-closed
```

## 5. 构建并托管前端

```bash
cd frontend
npm ci
npm run build          # 产物 frontend/dist
npm run preview        # 本地预览（或交由 nginx 静态托管 dist）
```

前端通过 `frontend/src/lib/api.js` 调用 `/api/Axx`；生产部署需把前端 `base` 指向服务端地址
（见 `frontend/vite.config` / 环境配置）。

---

## 6. 配置 LLM 网关（阶段二接入点）

服务端当前为**契约桩服务**（验证契约/监控/路由链路），真实 LLM 匹配在阶段二接入
（`scaffold/src/llm_match.py` 的 `MatchService` + `CostGuard` 已就绪，受 `cost_policy` 日硬上限约束）。
接入时通过 `.env` 注入网关地址与密钥（**密钥禁止入库**，见 `.env.example`）：
- `LLM_GATEWAY_URL`
- `LLM_API_KEY`

## 7. 本机重客户端（用户本机运行）

```bash
cd <repo>
python scaffold/src/local_agent.py     # 演示编排（MockAdapter，不触真实浏览器/凭据）
```
真实投递需用户本机注入 Playwright 适配器 + 自己的平台账号 Cookie（物理动作，仅用户）。
`DeliveryOrchestrator` 已实现：候选过滤、半自动确认闸门、当日限额、幂等去重、验证码暂停，
并发出对齐 `domain-events` 契约的 `apply.status.changed` 事件（驱动护栏3 成功率/封号率）。

---

## 8. 监控接入（护栏3）

`/metrics` 输出 Prometheus 文本。运维接入：
```yaml
# prometheus.yml 片段
scrape_configs:
  - job_name: 'rat-server'
    static_configs:
      - targets: ['rat-server:8080']
```
告警规则基于 `rat_ban_rate` / `rat_error_rate` / `rat_llm_cost_cents` 超阈值（阈值见
`design/guardrails/pre-deploy-safety-checklist.md` 的 go/no-go 闸门）。
