项目中遇到的最大技术挑战？

如果重做这个项目，你会改进什么？

技术问题
10 个高频题
▼
JVM 内存区域与 GC 机制？
运行时数据区：堆、虚拟机栈、本地方法栈、方法区（元空间）、程序计数器。GC：新生代（复制算法，Eden/S0/S1）→ 老年代（标记-清除/标记-整理），常用收集器 G1/ZGC。线上排查常用 jmap/jstat/jstack，Full GC 频繁可考虑堆大小、对象分配与回收热点。
MySQL 索引优化与慢查询排查？
B+ 树结构、聚簇/非聚簇索引、联合索引最左前缀、覆盖索引与回表。慢查询先打开 slow_log，EXPLAIN 看 type/rows/key，避免索引失效（隐式转换、函数运算、%前缀模糊）。
缓存一致性如何保证？
常用 Cache Aside：读先查缓存，写先更新 DB 再删缓存（避免删除失败加延迟双删或订阅 binlog 异步淘汰）。高并发下防止穿透（布隆过滤）、击穿（互斥锁/热点永不过期）、雪崩（过期时间打散 + 多级缓存）。
synchronized 与 ReentrantLock 的区别？
synchronized 由 JVM 管（无锁→偏向→轻量→重量级），自动释放；ReentrantLock 是 API 实现，支持可中断、可超时、公平锁、多条件等待。两者都可重入。
分布式事务的几种方案？
2PC/3PC（强一致、性能差）、TCC（Try-Confirm-Cancel、侵入性强）、本地消息表 + 消息队列（最终一致性、实现简单）、SEATA AT 模式（无侵入、自动回滚，适合一致性要求不极端场景）。
Kafka 如何保证消息不丢失不重复？
生产端 acks=all + 重试；Broker 端副本 ISR 同步；消费端手动提交 offset + 消费幂等（唯一键去重 / 状态机）。至少一次语义下靠消费幂等兜底。
Spring 的 IOC 与 AOP 本质？
IOC 反转控制：对象创建与依赖注入交给容器管理；生命周期：实例化→属性填充→初始化(InitializingBean/@PostConstruct)→使用→销毁。AOP 基于动态代理：JDK 代理（接口）与 CGLIB（子类），切面处理日志/事务/权限。
Redis 持久化机制？
RDB：定时快照、恢复快、可能丢数据；AOF：追加日志、fsync 策略控制丢失窗口，重写压缩体积；生产常用 AOF + RDB 混合（4.0+）。
什么是 ThreadLocal？会内存泄漏吗？
线程本地变量，存储于 Thread 的 ThreadLocalMap，key 为弱引用、value 为强引用；线程池复用场景下若不复用 remove() 会因 value 无法回收导致泄漏，用完必须 remove()。
如何设计一个高可用系统？
冗余部署（多副本 + 负载均衡）、故障隔离（熔断/降级/限流，如 Sentinel）、无状态设计、数据多副本（主从 + 容灾）、全链路监控与告警、定期压测与故障演练。
