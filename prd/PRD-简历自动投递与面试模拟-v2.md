# 产品需求文档：AI 简历助手 — 自动投递与面试模拟

> 2026-08-13 · v2.0（插件版）  
> 场景路由：0-to-1 产品 + AI 产品 · 深度：中等

---

| 维度 | 分类 |

## 2. 需求背景

应届生和社招求职者每天需要在 BOSS 直聘、猎聘、前程无忧、智联招聘等多个平台之间切换，手动筛选和投递岗位，耗时 2-3 小时。投递后被动等待回复，收到面试邀请时往往准备时间不足。市场上已有的开源自动投递工具（GetJobs、JobClaw、Boss Batch Push）均停留在 CLI 脚本层面，无可视化界面、无智能匹配策略、投递后无面试准备联动。

对求职者而言，问题不止于平台数量多——不同平台覆盖的岗位类型各有侧重：BOSS 直聘覆盖互联网社招，应届生求职网和高校就业平台覆盖校招，国聘网覆盖央企国企，猎聘覆盖中高端岗位。求职者需要一套系统，能够统一管理所有这些平台的投递，并随着新平台的出现灵活扩展。

---

## 3. 需求目标

- 将每日多平台投递从手动 2-3 小时缩短为一键确认 + 自动执行
- 投递与面试准备形成闭环，投递成功后自动触发岗位相关的面试题预测和话术建议
- 平台接入架构支持热插拔，新平台可在不修改核心逻辑的前提下通过适配器扩展

| 指标 | 目标值 | 说明 |
|------|-------|------|
| 单日投递量 | 80-100 份 | 覆盖所有已接入平台，低于各平台上限保留安全余量 |
| HR 查看率 | 对比手动投递提升 ≥30% | 通过匹配度筛选和时段优化 |
| 面试邀请率 | 对比手动投递提升 ≥20% | 仅投递匹配度 > 60% 的岗位 |
| 投递到面试准备启动间隔 | < 5 分钟 | 投递成功后自动触发 AI 准备 |
| 平台接入扩展耗时 | ≤ 2 人天/新平台 | 通过适配器架构实现 |

## 4. 竞品调研

### 4.1 竞品概况

| 产品/工具 | 类型 | 界面 | 自动投递 | 智能匹配 | 面试准备 | 平台覆盖 |
|-----------|------|------|---------|---------|---------|---------|
| GetJobs | 开源 CLI | 无 | 部分平台 | 无 | 无 | 1-2 个 |
| JobClaw | 开源脚本 | 无 | 多平台 | 基础关键词 | 无 | 3-4 个 |
| Boss Batch Push | 开源脚本 | 无 | BOSS 直聘 | 无 | 无 | 1 个 |
| 知页简历 | 商业产品 | 有 | 无 | 无 | 基础题库 | 不适用 |
| 超级简历 | 商业产品 | 有 | 无 | 无 | 模拟面试 | 不适用 |
| **本产品** | 商业产品 | 有 | 多平台 | AI 匹配 | AI 生成 | 可扩展架构 |

### 4.2 竞品方法论提炼

所有开源投递工具均采用 Playwright 模拟真人浏览器操作，核心手段包括随机延迟（正态分布）、随机鼠标轨迹（贝塞尔曲线）、Cookie 持久化。共同结论是：**无公开 API，所有平台均需通过浏览器模拟实现投递**。开源工具停留在"脚本"层面，商业产品（知页、超级简历）聚焦简历制作和面试题库，均未将"自动投递"作为核心功能。"智能投递策略 + 面试准备联动"是目前市场的明确空白。

### 5.1 功能总览

|---|------|---------|

**业务逻辑**：

- **内容与样式分离**：简历内容（文本数据）与视觉样式（模板、主题色、字体）独立存储。切换模板时仅替换 CSS 修饰器，不改变底层数据模型。
- **模板机制**：CSS modifier 方案，每个模板定义一组 CSS 变量（`--font-family`、`--heading-color`、`--section-gap`），切换时通过 JS 替换根元素的 class 实现即时换肤。主题色作为独立维度叠加，不与模板绑定。
- **ATS 评分**：基于简历内容完整度、关键词密度、排版规范性、与目标岗位的语义匹配度（通过 LLM 分析）综合计算得分。评分结果分解为具体改进建议，每条建议可点击"采纳"自动修改对应内容块。

**交互逻辑**：
- 点击左栏模块 → 中栏自动滚动并高亮对应内容块
- 中栏内容块双击 → 进入 contenteditable 编辑模式，编辑后自动保存
- 右栏模板点击 → 中栏即时切换模板样式，缩略图同步更新

**边界与异常**：
- 用户无简历内容时，展示空状态引导页，提示新建简历或导入已有简历文件
- ATS 评分为 0 时，展示"请先完善简历内容"提示
- 导出 PDF 时若简历内容为空，阻止导出并提示用户先填写内容

**业务逻辑**：

- **岗位匹配度计算**：通过 LLM（DeepSeek）分析岗位 JD 与用户简历的语义匹配度，输出 0-100 的分数及匹配理由。仅展示匹配度 > 60% 的岗位，匹配度 < 40% 的岗位自动过滤。
- **匹配度标签**：颜色编码——绿色（≥80%）、蓝色（60-79%）、灰色（<60% 但用户手动调整阈值后展示）。标签旁显示简要匹配理由。
- **多平台覆盖**：岗位来源聚合所有已接入平台，每条岗位标注来源平台。用户可筛选特定平台或全部平台。
- **投递状态跟踪**：未投递 → 待投递（队列中）→ 投递中 → 已投递（含时间戳）→ 投递失败（含原因）→ HR 已查看 → 已发面试邀请 → 不合适。

**边界与异常**：
- 用户未创建简历时，展示 resume-banner 提示条
- 用户有多个方向简历时，展示"当前投递所用简历"切换器，支持手动选择或"自动匹配"模式
- 投递队列为空时，展示空状态："暂无待投递岗位，建议调整筛选条件或扩大搜索范围"

#### 模块 3：自动投递策略引擎

**架构总览**：

```
┌─────────────────────────────────────────────────────────────────┐
│                    预处理层                                      │
│  岗位采集 → AI 匹配打分 → 过滤规则链 → 优先级排序              │
└──────────────────────────┬──────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│                    调度层                                        │
│  平台路由 → 时段推荐 → 频率控制 → 限额管理 → 简历版本选择      │
└──────────────────────────┬──────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│                    执行层                                        │
│  浏览器模拟 → 防检测 → 状态记录 → 异常处理                     │
│  ┌──────────────────────────────────────────────────────┐       │
│  │  平台适配器 1 (BOSS) │ 平台适配器 2 (猎聘) │ ...     │       │
│  │  每个适配器实现: login / search / apply / checkStatus │       │
│  └──────────────────────────────────────────────────────┘       │
└──────────────────────────┬──────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│                    反馈层                                        │
│  投递报告 → 响应率跟踪 → 动态调优 → 策略学习                   │
└─────────────────────────────────────────────────────────────────┘
```

**预处理层**：
- AI 匹配打分：LLM 分析岗位 JD 与简历的匹配度
- 过滤规则链：排除外包/外派、培训公司、僵尸岗（HR 超 7 天未活跃）、薪资范围不符、重复投递
- 优先级排序：按匹配度降序 + 发布时间倒序排列

**调度层**：

| 时段 | 投递数量 | 策略说明 |
|------|---------|---------|
| 09:30-11:30 | 30-40 份 | HR 上午黄金时段 |
| 14:30-16:00 | 30-40 份 | 下午黄金时段，周三周四最佳 |
| 19:00-20:30 | 20-30 份 | 互联网/科技公司 HR 加班时段 |
| **每日合计** | **80-100 份** | 低于各平台上限，保留安全余量 |

限额策略：单次投递不超过 50 个，两次操作间隔 30 分钟以上；单平台日上限设为平台限制的 70%；同一岗位间隔至少 1 个月且有简历更新后可重新投递。

**执行层**：
- 防检测五重保障：随机延迟（正态分布，3-8 秒）、行为模拟（贝塞尔曲线鼠标轨迹、随机滚动、随机 User-Agent）、验证码检测暂停、Cookie 持久化加密存储、黑名单机制
- 异常处理：限额已满→暂停该平台次日恢复；验证码触发→暂停所有任务通知用户；账号异常→停止所有任务；网络错误→重试 3 次后跳过

**反馈层**：
- 投递报告自动生成（成功数/失败数/原因/黑名单更新）
- 按平台统计 HR 查看率、回复率、面试邀请率，低于阈值则减少该平台投递量
- 每月复盘各平台响应率，响应率 < 10% 则减少投递频率并优化简历关键词

**策略配置面板**：

| 配置项 | 类型 | 默认值 | 说明 |
|-------|------|-------|------|
| 每日投递上限 | 滑块（20-150） | 80 | 所有平台合计 |
| 匹配度阈值 | 滑块（40-90） | 60 | 低于此值不投递 |
| 投递时段 | 多选开关 | 早中晚全开 | 可单独关闭某时段 |
| 启用平台 | 多选开关 | 全部开启 | 可关闭特定平台 |
| 自动简历选择 | 开关 | 开启 | 自动选择匹配度最高的简历版本 |
| 投递后自动面试准备 | 开关 | 开启 | 投递后自动生成面试准备内容 |
| 平台扩展 | 管理入口 | — | 查看/添加/配置平台适配器 |

#### 模块 4：平台适配器系统

这是本版本 PRD 的核心新增设计——平台接入不再硬编码，而是通过适配器架构实现热插拔扩展。

**适配器接口契约**：

每个平台适配器必须实现以下接口：

```
interface PlatformAdapter {
  // 元信息
  platformId: string          // 平台唯一标识，如 "boss", "yingjiesheng"
  platformName: string        // 平台显示名称，如 "BOSS直聘", "应届生求职网"
  platformType: 'social' | 'campus' | 'state-owned' | 'headhunter' | 'other'
  
  // 认证
  login(credentials: Credentials): Promise<LoginResult>
  checkLoginStatus(): Promise<boolean>
  logout(): Promise<void>
  
  // 岗位操作
  searchJobs(query: JobQuery): Promise<Job[]>
  getJobDetail(jobId: string): Promise<JobDetail>
  
  // 投递操作
  applyJob(jobId: string, resume: Resume): Promise<ApplyResult>
  checkApplyStatus(jobId: string): Promise<ApplyStatus>
  
  // 状态
  getDailyQuota(): Promise<{ used: number; total: number }>
  isAvailable(): Promise<boolean>
}
```

**平台接入清单**：

| 平台 | 类型 | 接入状态 | 优先级 | 说明 |
|------|------|---------|-------|------|
| BOSS 直聘 | 社招 | 已接入 | P0 | 互联网社招主力 |
| 猎聘 | 社招/中高端 | 已接入 | P0 | 中高端岗位补充 |
| 前程无忧 | 综合 | 已接入 | P1 | 传统渠道 |
| 智联招聘 | 综合 | 已接入 | P1 | 兜底渠道 |
| 拉勾 | 互联网 | 已接入 | P2 | 低频渠道 |
| **应届生求职网** | **校招** | **待接入** | **P0** | **应届生校招主力** |
| **高校就业指导中心平台** | **校招** | **待接入** | **P0** | **各高校自有平台，需适配器模板** |
| **国聘网** | **央企国企** | **待接入** | **P0** | **央企国企招聘主渠道** |
| **牛客网** | **校招/技术** | **待接入** | **P1** | **技术类校招+笔试面试** |
| **猎聘校园** | **校招** | **待接入** | **P1** | **校招补充渠道** |
| 其他平台 | 待定 | 可扩展 | — | 通过适配器接口接入 |

**高校平台适配器模板**：考虑到国内高校就业平台大多基于少数几家 SaaS 供应商（如就业宝、完美校园、云研科技等），平台适配器系统提供"通用高校模板"，覆盖 80% 同构平台，剩余 20% 通过自定义适配器扩展。

**扩展流程**：
1. 用户通过"平台管理"界面添加新平台
2. 系统检测平台类型：若为已知模板（如"高校就业平台 - 就业宝版"），自动加载对应适配器
3. 若为全新平台，用户填写平台基本信息，系统生成适配器骨架代码
4. 开发者完成适配器实现，通过灰度测试后上线
5. 适配器可通过社区贡献机制共享——用户可导入他人开发的适配器

**联动数据流**：

## 6. AI 产品专项

### 6.1 LLM 使用场景

| 场景 | 能力 | 输入 | 输出 |
|------|------|------|------|
| 岗位匹配度评分 | 语义相似度 + 关键技能匹配 | 岗位 JD + 用户简历 | 匹配分数 (0-100) + 匹配理由 |
| 面试题生成 | 基于上下文的生成 | 岗位 JD + 简历项目经历 | 题目列表 + 参考答案 + 难度标签 |
| 面试作答评估 | 多维度评分 | 作答文本 + 标准答案 | 各维度评分 + 改进建议 |
| ATS 简历评分 | 内容完整性 + 关键词密度 | 简历全文 | 综合评分 + 改进建议列表 |
| 简历内容优化 | 文本润色 + 改写 | 原始内容 + 目标岗位 | 优化后的简历文本 |
| 自我介绍生成 | 结构化摘要 | 简历全文 | 1 分钟 / 3 分钟版本 |

### 6.2 准确度定义与评估体系

**任务成功标准**：

| 场景 | 成功标准 | 质量维度 | 主观/客观 |
|------|---------|---------|-----------|
| 岗位匹配度评分 | 推荐岗位与用户实际投递意愿的吻合度 ≥ 80% | 正确性、相关性 | 可客观验证 |
| 面试题生成 | 题目覆盖 JD 中 80% 以上的技术关键词 | 完整性、相关性 | 半客观 |
| 面试作答评估 | 评估结果与资深面试官评分的偏差 ≤ 1 分 | 正确性、一致性 | 主观 |
| ATS 简历评分 | 评分与 HR 筛选结果的排序一致性 ≥ 70% | 正确性 | 可客观验证 |
| 简历优化 | 用户采纳率 ≥ 60% | 可读性、有效性 | 主观 |

**评估体系**：

- 离线评估：构建标准样本集（含边界样本和负样本），每轮模型更新后回归测试
- 人工复核：产品经理每周抽样评审生成结果，记录 bad case 并归因
- 在线反馈：通过行为指标（编辑率、复制率、采纳率、重新生成率、废弃率）和用户反馈（点赞/点踩、问题标签）持续监控

**Go/No-go 标准**：

| 维度 | 可上线标准 |
|------|-----------|
| 准确度 | 离线评估通过率 ≥ 90% |
| 体验 | 用户端响应延迟在 §6.4 规定的范围内 |
| 安全 | 不生成违规内容，不泄露用户简历数据 |
| 成本 | 单次 LLM 调用成本在预算范围内 |
| 运维 | 有降级方案和监控告警 |

### 6.3 回退机制

| 场景 | 首选项 | 降级 1 | 降级 2 |
|------|-------|--------|--------|
| 匹配度评分 | LLM 语义匹配 | 规则引擎关键词匹配 | 随机排序 |
| 面试题生成 | LLM 生成 + 题库 | 纯题库匹配 | 预设模板题 |
| 面试评估 | LLM 多维度评分 | 仅提供参考建议 | 不评分 |
| ATS 评分 | LLM + 规则综合 | 纯规则关键词评分 | 仅展示完整度 |
| 简历优化 | LLM 改写 | 提供多个版本 | 语法检查 |

### 6.4 延迟要求

| 场景 | 最大可接受延迟 | 说明 |
|------|---------------|------|
| 匹配度计算 | 5 秒 | 同步展示，需快速响应 |
| 面试题生成 | 30 秒 | 异步后台任务 |
| 作答评估 | 3 秒 | 对话式交互，需及时反馈 |
| 简历优化 | 10 秒 | 用户点击 AI 生成按钮后等待 |
| 投递后联动 | 5 分钟 | 后台异步，用户无需等待 |

### 7.2 风险清单

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 平台反爬升级导致投递失败 | 高 | 高 | 模块化适配器设计，单一平台升级不影响其他平台；预留人工处理通道 |

| 高校平台异构化程度高 | 中 | 中 | 通用模板覆盖 80% 同构平台，剩余 20% 通过自定义适配器 |
| 用户隐私与数据安全 | 低 | 高 | 简历数据本地加密存储，平台 Cookie 加密，不向第三方传输 |
