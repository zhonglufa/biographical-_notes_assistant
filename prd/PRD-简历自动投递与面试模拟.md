# 产品需求文档：AI 简历助手 — 自动投递与面试模拟

> 文档版本：v1.0  
> 更新日期：2026-08-13  
> 文档状态：初稿

---

## 1. 需求背景

### 1.1 业务触发

求职者在当前招聘市场中面临的核心矛盾是 **信息过载与匹配效率低下**。主流招聘平台（BOSS直聘、猎聘、前程无忧、智联招聘、拉勾）各自拥有独立的岗位库和投递流程，求职者每天需要：

- 在多个平台间反复切换，手动筛选岗位
- 对每个岗位逐一投递，重复填写或确认简历版本
- 投递后被动等待回复，缺乏主动的面试准备辅助

用户调研和竞品分析表明，市面上的"自动投递工具"多以开源脚本形式存在（如 GetJobs、JobClaw、Boss Batch Push），而非面向普通求职者的产品化解决方案。这些工具存在三个共同短板：**无界面、无策略、无后续**——没有可视化操作界面，缺乏智能匹配策略，投递后没有任何面试准备联动。

### 1.2 用户痛点

| 痛点 | 场景描述 | 受影响用户 |
|------|---------|-----------|
| 多平台重复操作 | 每天在 BOSS、猎聘、前程无忧之间重复筛选和投递，耗时 2-3 小时 | 所有求职者 |
| 盲目海投效率低 | 没有匹配度评估，大量投递与自身背景不匹配的岗位，回复率低 | 中高级求职者 |
| 投递后无跟进 | 投递后被动等待，收到面试邀请时准备时间不足 | 所有求职者 |
| 简历版本管理混乱 | 不同方向岗位需要不同侧重点的简历，手动管理多版本易出错 | 跨方向求职者 |
| 面试准备缺乏针对性 | 通用面试准备无法覆盖特定岗位 JD 中的技术栈和业务场景 | 技术/专业岗位求职者 |

### 1.3 调研数据支撑

- 主流招聘平台中，BOSS直聘日均投递上限约 150 次，猎聘打招呼无限制但主动发消息有上限，前程无忧同一岗位 7 天不可重复投递 [Research-backed]
- 开源自动投递工具无一例外使用 Playwright 模拟浏览器操作，且均面临反爬升级带来的维护挑战 [Research-backed]
- 用户反馈中，"投递后自动生成面试准备"的需求出现在多个求职社区讨论中 [PM judgment]

## 2. 需求目标

### 2.1 定性目标

- 将求职者的每日多平台投递操作从手动 2-3 小时缩短为 **一键确认 + 自动执行**
- 投递成功率（HR 查看率）通过策略优化提升至行业平均水平以上
- 投递与面试准备形成闭环，投递成功后自动触发岗位相关的面试题预测和话术建议

### 2.2 定量目标（待上线后验证）

| 指标 | 目标值 | 说明 |
|------|-------|------|
| 单日投递量 | 80-100 份/天 | 覆盖多平台，低于各平台上限保留安全余量 |
| HR 查看率 | 对比手动投递提升 ≥30% | 通过匹配度筛选和时段优化提升 |
| 面试邀请率 | 对比手动投递提升 ≥20% | 仅投递匹配度 > 60% 的岗位 |
| 投递到面试准备启动间隔 | < 5 分钟 | 投递成功后自动触发 AI 准备 |

## 3. 市场与竞品分析

### 3.1 竞品概况

| 产品/工具 | 类型 | 界面 | 自动投递 | 智能匹配 | 面试准备 | 维护状态 |
|-----------|------|------|---------|---------|---------|---------|
| **GetJobs** | 开源 CLI 工具 | 无 | 部分平台 | 无 | 无 | 社区维护 |
| **JobClaw** | 开源脚本 | 无 | 多平台 | 基础关键词 | 无 | 间歇更新 |
| **Boss Batch Push** | 开源脚本 | 无 | BOSS直聘 | 无 | 无 | 活跃维护 |
| **知页简历** | 商业产品 | 有 | 无 | 无 | 基础题库 | 商业运营 |
| **超级简历** | 商业产品 | 有 | 无 | 无 | 模拟面试 | 商业运营 |
| **本产品** | 商业产品 | 有 | 多平台 | AI 匹配 | AI 生成 | — |

### 3.2 竞品方法论提炼

**反爬与防检测策略**：所有开源投递工具均采用 Playwright 模拟真人浏览器操作，核心手段包括随机延迟（正态分布而非均匀分布）、随机鼠标轨迹（贝塞尔曲线）、Cookie 持久化以减少重复登录。这些技术方案的共同结论是：**无公开 API，所有平台均需通过浏览器模拟实现投递**。

**产品化空白**：开源工具停留在"脚本"层面，商业产品（如知页、超级简历）聚焦简历制作和面试题库，但均未将"自动投递"作为核心功能。这意味着"智能投递策略 + 面试准备联动"是目前市场的明确空白。

## 4. 用户角色与场景

### 4.1 目标用户画像

| 角色 | 求职阶段 | 核心需求 | 使用频率 |
|------|---------|---------|---------|
| 应届毕业生 | 首次求职，海投为主 | 多平台批量投递，快速覆盖 | 每日 |
| 1-3 年经验者 | 跳槽换工作，目标明确 | 精准匹配，减少无效投递 | 工作日每日 |
| 5+ 年资深者 | 被动求职，观望机会 | 少量高质量投递，深度面试准备 | 每周 2-3 次 |
| 跨方向求职者 | 同时投递多个方向（如 Java + 前端） | 多版本简历管理，按岗位自动匹配 | 工作日每日 |

### 4.2 核心使用场景

**场景一：每日批量投递**

用户早晨打开系统，查看 AI 已筛选的岗位列表（匹配度 > 60%），一键确认投递队列，系统自动按平台策略分发投递。用户可实时查看投递进度和结果反馈。

**场景二：投递后自动面试准备**

某岗位投递成功（HR 已查看或发来面试邀请），系统自动分析该岗位 JD，生成面试预测题（技术题 + 行为题）和话术建议，并推送到面试备战模块。

**场景三：简历版本自动适配**

用户在不同方向（如 Java 后端、前端、算法）各有简历版本。投递时系统自动比对岗位 JD 与各版本简历的匹配度，选择匹配度最高的版本投递，并提示用户可调整。

**场景四：面试模拟自主练习**

用户进入面试备战页面，选择"自我介绍"、"项目介绍"、"技术问题"、"行为问题"等分类，逐项展开练习。AI 根据用户简历和所选岗位生成模拟题目，用户作答后可获得 AI 评估反馈。

## 5. 功能需求详述

### 5.1 简历编辑工作台

#### 页面布局

工作台采用三栏布局：

| 区域 | 栏位 | 功能 |
|------|------|------|
| 左栏 | 模块管理 | 6 个简历模块（个人信息、教育背景、工作经历、项目经历、技能标签、自我评价），可拖拽排序，每个模块配有 AI 生成按钮 |
| 中栏 | PDF 实时预览 | A4 白纸 1:1 效果，内容块支持 `contenteditable` 直接编辑，模板/主题切换实时反映，支持缩放 75%/100%/150% + 全屏 |
| 右栏 | 模板滤镜 + AI | 3 分类 6 款模板，真实内容缩略图预览；6 色主题独立叠加；ATS 评分 + 3 条 AI 建议可采纳/忽略；导出 PDF/Word/HTML |

#### 业务逻辑

**内容与样式分离**：简历内容（文本数据）与视觉样式（模板、主题色、字体）独立存储。切换模板时仅替换 CSS 修饰器，不改变底层数据模型。这是确保"模板滤镜"模式（即知页简历的看齐策略）可落地的核心设计决策。

**模板机制**：采用 CSS modifier 类名方案，每个模板定义一组 CSS 变量（`--font-family`、`--heading-color`、`--section-gap` 等），切换时通过 JS 替换根元素的 class 实现即时换肤。主题色作为独立维度叠加，不与模板绑定。

**ATS 评分**：基于简历内容完整度、关键词密度、排版规范性、与目标岗位的语义匹配度（通过 LLM 分析）综合计算得分。评分结果分解为具体改进建议，每条建议可点击"采纳"自动修改对应内容块。

#### 交互逻辑

- 点击左栏模块 → 中栏自动滚动并高亮对应内容块
- 中栏内容块双击 → 进入 `contenteditable` 编辑模式，编辑后自动保存
- 右栏模板点击 → 中栏即时切换模板样式，缩略图同步更新
- 右栏主题色点击 → 中栏立即应用新色系

#### 边界与异常

- 用户无简历内容时，展示空状态引导页，提示新建简历或导入已有简历文件
- ATS 评分为 0 时，展示"请先完善简历内容"提示，AI 建议区域显示"添加更多内容以获得个性化建议"
- 导出 PDF 时若简历内容为空，阻止导出并提示用户先填写内容

### 5.2 岗位浏览与投递

#### 页面布局

| 区域 | 功能 |
|------|------|
| 顶部筛选栏 | 关键词搜索、城市/薪资/经验年限筛选，多选互不冲突 |
| 岗位列表 | 卡片式展示，每张卡片包含：公司 Logo、岗位名称、薪资范围、匹配度标签（颜色编码）、投递状态 |
| 列表顶部 | 全选复选框 + 批量操作按钮（一键投递、加入收藏、忽略） |
| 底部 | 三段式 Footer：左品牌信息、中功能标签、右版本号 |

#### 业务逻辑

**岗位匹配度计算**：系统通过 LLM（DeepSeek）分析岗位 JD 与用户简历的语义匹配度，输出 0-100 的分数及匹配理由。仅展示匹配度 > 60% 的岗位，匹配度 < 40% 的岗位自动过滤。

**匹配度标签**：采用颜色编码——绿色（≥80%）、蓝色（60-79%）、灰色（<60% 但用户手动调整阈值后展示）。标签旁显示简要匹配理由（如"Java 技能匹配度高，但缺少微服务经验"）。

**多平台覆盖**：岗位来源聚合 BOSS直聘、猎聘、前程无忧等主流平台，每条岗位标注来源平台。用户可筛选特定平台或全部平台。

**投递状态跟踪**：每个岗位的投递状态包括：未投递、待投递（在队列中）、投递中、已投递（含时间戳）、投递失败（含失败原因）、HR 已查看、已发面试邀请、不合适。

#### 边界与异常

- 用户未创建简历时，岗位列表顶部展示 **resume-banner 提示条**，说明"建议先完善简历，匹配度计算依赖于简历内容。即使没有简历也可浏览岗位，但匹配度无法准确评估"
- 当用户有多个方向简历时，展示"当前投递所用简历"切换器，用户可手动选择或使用"自动匹配"模式
- 投递队列为空时，展示空状态："暂无待投递岗位，建议调整筛选条件或扩大搜索范围"

### 5.3 自动投递策略引擎

#### 架构总览

投递策略引擎采用四层架构：

```
预处理层：岗位采集 → AI 匹配 → 优先级排序
    ↓
调度层：平台路由 → 时段推荐 → 频率控制 → 限额管理
    ↓
执行层：浏览器模拟 → 防检测 → 状态记录 → 异常处理
    ↓
反馈层：投递结果 → 面试邀请 → 策略学习 → 动态调优
```

#### 5.3.1 预处理层

**AI 匹配打分**：使用 LLM 分析岗位 JD 与用户简历的匹配度，输出匹配分数 + 匹配理由。仅投递匹配度 > 60% 的岗位。

**过滤规则链**（可配置）：

| 规则 | 说明 | 默认启用 |
|------|------|---------|
| 排除外包/外派 | 识别岗位描述中的外包特征词（"外派"、"驻场"、"外包"） | 是 |
| 排除培训公司 | 识别培训公司特征（"实训"、"培训贷"、"先培训后上岗"） | 是 |
| 跳过僵尸岗 | HR 超过 7 天未活跃的岗位 | 是 |
| 薪资范围过滤 | 薪资低于用户设定的最低期望值时自动跳过 | 是 |
| 重复投递过滤 | 自动跳过已投递记录，间隔至少 1 个月且有简历更新后重新开放 | 是 |

**优先级排序**：按匹配度降序 + 发布时间倒序排列，优先投递高匹配 + 新发布岗位。

#### 5.3.2 调度层

**每日投递节奏**：

| 时段 | 投递数量 | 策略说明 |
|------|---------|---------|
| 09:30-11:30 | 30-40 份 | HR 上午黄金时段，处理简历效率最高 |
| 14:30-16:00 | 30-40 份 | 下午黄金时段，周三周四最佳 |
| 19:00-20:30 | 20-30 份 | 互联网/科技公司 HR 加班时段 |
| **每日合计** | **80-100 份** | 低于各平台上限，保留安全余量 |

**限额策略**：

- 单次投递不超过 50 个，两次操作间隔 30 分钟以上
- 单平台日上限设为平台限制的 70%（如 BOSS 设 100/天，留 50 余量）
- 同一岗位不重复投递，间隔至少 1 个月且有简历优化后

**平台路由策略**：

| 平台 | 定位 | 投递量占比 |
|------|------|-----------|
| BOSS直聘 | 主力渠道 | 50% |
| 猎聘 | 批量补充 | 25% |
| 前程无忧 | 补充性渠道 | 15% |
| 智联招聘 | 兜底渠道 | 10% |
| 拉勾 | 最低优先级 | 可选关闭 |

#### 5.3.3 执行层

**防检测五重保障**：

1. **随机延迟**：每次投递间隔 3-8 秒（可配置），用正态分布模拟人类节奏
2. **行为模拟**：随机鼠标轨迹（贝塞尔曲线）、随机页面滚动、随机 User-Agent
3. **验证码检测**：遇到滑块/图形验证码自动暂停，通知用户人工处理
4. **Cookie 持久化**：登录后加密存储 Cookie，大部分平台每周仅需扫码一次
5. **黑名单机制**：自动记录发送"不合适"回复的公司，避免重复投递

**异常处理流程**：

```
投递失败 → 判断错误类型
 ├─ 限额已满 → 暂停该平台，次日恢复
 ├─ 验证码触发 → 暂停所有任务，通知用户处理
 ├─ 账号异常 → 停止所有任务，通知用户检查账号
 └─ 网络错误 → 重试 3 次，仍失败则跳过
```

#### 5.3.4 反馈层

- **投递报告**：每次投递结束后自动生成报告（成功数/失败数/失败原因/黑名单更新）
- **响应率跟踪**：按平台统计 HR 查看率、回复率、面试邀请率，低于阈值则减少该平台投递量
- **动态调优**：每月复盘各平台响应率，若某平台响应率 < 10%，减少投递频率并优化简历关键词

#### 策略配置面板

用户可见的配置项（投递页面右侧面板）：

| 配置项 | 类型 | 默认值 | 说明 |
|-------|------|-------|------|
| 每日投递上限 | 滑块（20-150） | 80 | 所有平台合计 |
| 匹配度阈值 | 滑块（40-90） | 60 | 低于此值不投递 |
| 投递时段 | 多选开关 | 早中晚全开 | 可单独关闭某时段 |
| 启用平台 | 多选开关 | 全部开启 | 可关闭特定平台 |
| 自动简历选择 | 开关 | 开启 | 自动选择匹配度最高的简历版本 |
| 投递后自动面试准备 | 开关 | 开启 | 投递成功后自动生成面试准备内容 |

### 5.4 面试模拟备战

#### 页面布局

面试备战页采用卡片网格布局，每张卡片代表一个备战分类：

| 卡片 | 分类 | 内容说明 |
|------|------|---------|
| 自我介绍 | 通用 | 1 分钟 / 3 分钟版本，AI 根据简历生成 |
| 项目介绍 | 通用 | 基于简历项目经历，按 STAR 法则组织 |
| 技术问题 | 岗位相关 | 基于目标岗位 JD 的技术栈生成预测题 |
| 行为问题 | 通用 + 岗位 | 结合岗位文化（大厂/创业公司/外企）生成 |

#### 核心交互

**手风琴模式**：同一时刻仅展开一张卡片。展开一张卡片时自动收起其他卡片，避免网格同行卡片相互拉扯高度。网格采用 `align-items: start` 确保卡片高度独立。

**展开内容**：每张卡片展开后展示分类下的题目列表，每道题包含：
- 题目文本
- 参考答案（AI 生成，基于用户简历和岗位 JD）
- "模拟作答" 按钮（进入 AI 面试模拟对话）
- 难度标签（初级/中级/高级）

**初始状态**：首次进入时，"项目介绍"卡片默认展开，其余卡片折叠。后续用户的选择被记忆（localStorage）。

#### 边界与异常

- 用户无简历或未选岗位时，卡片展示 "请先完善简历并选择目标岗位" 提示
- 卡片内容为空时（如选了技术岗位但未生成技术题），展示 "AI 正在生成中，请稍后刷新" 状态
- 展开内容过多时（如技术问题 10+ 题），展开区域支持滚动，最大高度限制为 2400px

### 5.5 AI 面试模拟

#### 页面布局

| 区域 | 功能 |
|------|------|
| 顶部 | 对话信息栏（当前岗位名称、面试类型、已作答时间） |
| 中部 | 对话消息流（AI 面试官消息 + 用户作答，按时间顺序排列） |
| 底部 | 输入区域（文本输入框 + 语音输入按钮 + 发送键） |
| 开场面板 | 提示区（op-tip）：提示用户可开启摄像头、建议使用电脑端、准备纸笔 |

#### 业务逻辑

**面试类型**：

- **通用面试**：基于用户简历的通用问题，不绑定特定岗位
- **岗位定制面试**：基于具体岗位 JD，AI 生成该岗位的面试题，覆盖技术栈、业务场景、行为问题
- **压力面试**：连续追问模式，模拟高压面试场景
- **英文面试**：全英文对话，适用于外企岗位

**面试流程**：

1. AI 面试官发送开场白 + 第一道题目
2. 用户作答（文本或语音）
3. AI 对作答进行实时评估和追问（或进入下一题）
4. 面试结束后，生成综合评估报告（涵盖：回答质量、技术深度、表达清晰度、改进建议）

**评估系统**：AI 对每次作答的评估维度包括：

| 维度 | 说明 | 评分范围 |
|------|------|---------|
| 回答完整性 | 是否覆盖问题的核心要点 | 1-5 |
| 技术准确性 | 技术概念和方案表述是否正确 | 1-5 |
| 结构化表达 | 是否采用 STAR/金字塔等结构表达 | 1-5 |
| 与岗位匹配度 | 回答是否体现岗位所需的能力 | 1-5 |

#### 边界与异常

- 用户未选择岗位时，仅开放"通用面试"和"英文面试"
- 网络中断时，对话记录本地缓存，恢复后自动同步
- 语音输入识别失败时，提示用户可切换为文本输入

### 5.6 投递与面试准备联动

这是整个产品的闭环核心——投递不再是终点，而是面试准备的起点。

#### 联动触发条件

| 触发事件 | 联动动作 | 延迟 |
|---------|---------|------|
| 岗位投递成功（HR 未查看） | 后台分析 JD，预生成面试题，存入"待完善"状态 | 投递后立即 |
| HR 已查看简历 | 面试题从"待完善"转为"可查看"，推送通知 | 实时 |
| 收到面试邀请 | 生成完整面试准备包（含公司背景、岗位深度分析、模拟面试题），推送高优先级通知 | 实时 |
| 面试已完成 | 收集面试反馈，更新面试题库，优化后续预测 | 面试后 1 小时 |

#### 联动数据流

```
投递成功 → 后台异步任务：
 1. 提取岗位 JD 全文
 2. 调用 LLM 分析 JD 关键词和技术栈
 3. 匹配用户简历中的对应经历
 4. 生成面试题列表（技术题 + 行为题）
 5. 存入面试备战模块，标记状态
 6. 推送到前端（如用户在线）或静默等待
```

## 6. AI 产品专项

### 6.1 LLM 使用场景

| 场景 | 使用的 LLM 能力 | 输入 | 输出 |
|------|----------------|------|------|
| 岗位匹配度评分 | 语义相似度 + 关键技能匹配 | 岗位 JD + 用户简历 | 匹配分数 (0-100) + 匹配理由 |
| 面试题生成 | 基于上下文的生成 | 岗位 JD + 用户简历中的项目经历 | 题目列表 + 参考答案 + 难度标签 |
| 面试作答评估 | 多维度评分 | 用户作答文本 + 标准答案 | 各维度评分 + 改进建议 |
| ATS 简历评分 | 内容完整性 + 关键词密度 | 简历全文 | 综合评分 + 改进建议列表 |
| 简历内容优化 | 文本润色 + 改写 | 用户原始内容 + 目标岗位 | 优化后的简历文本 |
| 自我介绍生成 | 结构化摘要 | 用户简历全文 | 1 分钟 / 3 分钟版本 |

### 6.2 准确度与回退机制

| 场景 | 预期准确度 | 回退方案 |
|------|-----------|---------|
| 匹配度评分 | 中高（配合规则引擎） | 降级为基础关键词匹配 |
| 面试题生成 | 中高 | 提供题库兜底，LLM 生成失败时使用预设模板题 |
| 作答评估 | 中 | 仅提供参考建议，不替代人工判断 |
| ATS 评分 | 中 | 降级为基于规则的关键词评分 |
| 简历优化 | 中高 | 提供多个版本供用户选择 |

### 6.3 延迟要求

| 场景 | 最大可接受延迟 | 说明 |
|------|---------------|------|
| 匹配度计算 | 5 秒 | 同步展示在岗位列表，需快速响应 |
| 面试题生成 | 30 秒 | 异步后台任务，可接受较长时间 |
| 作答评估 | 3 秒 | 对话式交互，需及时反馈 |
| 简历优化 | 10 秒 | 用户点击 AI 生成按钮后等待 |
| 投递后联动 | 5 分钟 | 后台异步，用户无需等待 |

## 7. 术语表

| 术语 | 说明 |
|------|------|
| 匹配度 | 根据岗位 JD 与用户简历的语义相似度计算得出的 0-100 分数 |
| 模板滤镜 | 一种简历样式切换机制——内容不变，仅通过 CSS 修饰器切换视觉风格 |
| ATS 评分 | 简历系统对简历内容的自动评分，评估完整度、关键词密度和排版规范性 |
| 投递策略引擎 | 负责岗位匹配、投递调度、浏览器执行和结果反馈的四层系统 |
| 手风琴模式 | 同一时间仅展开一个面板的交互模式，展开新面板时自动收起当前面板 |
| 僵尸岗 | HR 超过 7 天未活跃的岗位，投递后获得回复的概率极低 |
