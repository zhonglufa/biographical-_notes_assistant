# ADR-020 原型交付方式

## 状态

已采纳

## 背景

在正式开发前，需要向团队（包括未来的开发者与投资人）交付可交互的产品原型，以验证产品设计、沟通需求、展示产品愿景。原型工具的选择直接影响沟通效率与迭代速度，需要一种"最低摩擦、最高真实感"的交付方式。

## 决策

采用 **HTML/CSS 高保真多页面原型**作为原型交付方式：

- 每页为一个独立的 HTML 文件，包含完整页面布局、交互与视觉设计。
- 页面顶部包含导航栏，可逐页面切换，而非单页滚动。
- 直接使用浏览器打开即可交互，无需任何工具依赖（Figma 账号、墨刀账号等）。
- 高保真度：视觉风格与实际产品几乎一致，交互（点击、hover、弹窗）均可真实操作。

## 理由

1. **零工具依赖**：任何人只需一个浏览器即可打开，无需注册账号、安装软件、学习操作，对外展示成本极低。
2. **可直接演化为前端页面骨架**：HTML/CSS 原型中的布局、组件、样式可在正式开发中直接复用，减少前端开发工作量。
3. **交互真实感强**：使用真实 CSS 样式与 JavaScript 交互，体验远优于 Figma 的点击跳转式原型，可用于用户测试验证。
4. **版本管理方便**：HTML 文件可用 Git 管理和对比，每次修改的差异一目了然，优于 Figma 的版本管理。
5. **适合独立开发者**：无需额外工具成本，一人即可完成从原型到开发的全部工作。

## 候选方案

1. **Figma 原型**：优点是协作功能强大、设计组件丰富、交互原型可配置；缺点是需要 Figma 账号、有一定的学习成本，且导出 HTML 需要额外工具或插件，无法直接演化为前端代码。
2. **墨刀原型**：优点是国内工具、中文支持好、有交互组件库；缺点是免费版功能受限、导出受限制，且原型无法直接转换为前端代码。

## 竞品参考

（该决策主要基于独立开发者"原型即开发"的工程效率考量；不少独立开发者采用 HTML/CSS 原型方式，直接跳过传统设计工具，提升从设计到开发的全链路效率。）

## 对开发的影响

1. 原型文件存放在 `prototype/` 目录下，与正式代码分离，使用独立的 HTML 文件，不引入构建工具或框架。
2. 原型中使用的 CSS 样式变量需要与最终设计系统保持一致，确保原型可直接演化为前端代码。
3. 原型导航栏需支持所有页面切换，并提供返回首页的入口，方便评审者自由浏览。
4. 原型仅包含前端交互，不涉及后端数据联调，所有数据使用静态 JSON 或 Mock 数据。
5. 原型完成后需进行至少一轮团队评审，收集反馈后修改定稿，正式开发前不再大规模修改原型。
