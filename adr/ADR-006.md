# ADR-006 批量投递模式

## 状态

已采纳

## 背景

用户希望"一次选择、批量投递"以提升效率，但全自动投递存在两类问题：一是法律与平台条款风险（绕过平台流程、可能被判定为违规操作）；二是用户体验差（用户对投递内容失去控制，误投、错投引发投诉）。需要在效率与安全之间找到平衡点。

## 决策

采用**购物车模式整合"岗位浏览+批量投递"为单一页面**，投递确认采用**半自动确认制**：

- **页面合并**：岗位浏览与批量投递整合为"岗位投递"单页面，减少用户操作路径。
- **购物车模式**：用户浏览岗位列表时勾选感兴趣的岗位加入"投递队列"（类似购物车），勾选后底部浮现操作栏。
- **逐份确认**：用户对队列中的每份投递点击"确认"按钮后，系统才执行提交。
- **低匹配度预警**：当岗位匹配度低于 60% 时，在确认弹窗中显示黄色警告标识。
- **投递配额**：页面顶部显示"今日已投 N 份/剩余配额"，防止超量投递触发风控。

## 理由

1. **参考 Simplify.jobs 成熟模式**：其 "autofill not auto-submit"（只填充不自动提交）模式已获得 100 万以上用户验证，兼顾效率与合规。
2. **全自动模式已被市场否定**：LazyApply 的全自动投递模式用户评分仅 2.4/5，主因即用户失去控制感与误投问题。
3. **购物车模式降低认知负担**：浏览岗位时勾选、统一确认，符合用户"先选后付"的心理模型，比分开页面更直观。
4. **降低法律与风控风险**：提交动作由用户主动发起，平台责任边界清晰，也显著降低被招聘平台风控封号概率。
5. **配额管理增强用户信任**：显示剩余投递额度，帮助用户合理分配投递计划。

## 候选方案

1. **全自动投递**：优点是效率最高；缺点是法律风险高、账号易被封禁、用户投诉多，LazyApply 2.4/5 的低评分已验证此模式失败。
2. **纯手动投递**：优点是零风险；缺点是效率低，无法体现产品核心价值，用户留存差。

## 竞品参考

Simplify.jobs 坚持 "autofill not auto-submit" 模式并获百万级用户验证；LazyApply 全自动模式评分仅 2.4/5。本项目采用与 Simplify.jobs 一致的半自动确认制。

## 对开发的影响

1. 投递流程必须实现"填充预览 → 用户确认 → 提交"三阶段，确认动作必须有显式 UI 交互与操作日志。
2. 岗位匹配度 < 60% 时，前端必须弹窗预警，且预警不能以静默方式跳过。
3. 每次提交必须携带用户确认的审计记录（时间、用户、岗位、表单快照），可追溯。
4. 自动填充数据必须允许用户编辑修改后再确认，禁止锁定表单。
5. 批量模式每次最多进入待确认队列的份数需设上限，避免误操作一次性提交过多。
