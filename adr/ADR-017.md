# ADR-017 用户体系

## 状态

已采纳

## 背景

产品需要支持多种登录方式以降低用户注册门槛，同时为后续商业化预留会员体系。登录方式的选择直接影响用户获取成本，会员体系的设计影响产品变现路径。

## 决策

**登录方式**：支持三类登录注册方式：

1. **邮箱注册登录**：邮箱 + 密码注册，或邮箱验证码登录。
2. **手机验证码登录**：手机号 + 短信验证码登录，国内主流。
3. **微信登录**：微信小程序内一键登录，PC 端扫码登录。

**会员体系**：预留三级会员体系，上线初期先开放免费版，后续逐步开放付费功能：

| 等级 | 权益 |
|------|------|
| 免费版 | 基础投递、简历优化 3 次/月、基础岗位推荐 |
| 会员版 | 无限投递、AI 简历无限优化、面试备战、详细数据统计 |
| Pro 版 | 会员版权益 + 批量投递、自动化投递、多账号管理、优先客服 |

## 理由

1. **覆盖主流登录方式**：邮箱 + 手机号 + 微信覆盖国内用户全部常用登录场景，最高程度降低注册门槛。
2. **微信登录适配小程序场景**：微信小程序原生支持一键登录，用户体验好、转化率高。
3. **会员体系为商业化铺路**：设计清晰的免费/会员/Pro 三级权益，上线后可根据运营数据逐步开放付费功能，无需后期重构用户模型。
4. **参考竞品模式**：超级简历使用邮箱+微信登录，会员体系也采用类似分层设计，验证了方案可行性。

## 候选方案

1. **仅邮箱注册登录**：优点是实现简单；缺点是国内用户手机号使用习惯更普遍，仅邮箱注册流失率较高。
2. **仅手机号注册登录**：优点是触达率高；缺点是海外用户或无手机用户无法注册，且无法在微信小程序中实现一键登录。

## 竞品参考

超级简历（Zhiyeji）使用邮箱注册 + 微信登录两种方式，会员体系分为免费/付费两级；本项目在超级简历方案基础上增加手机号登录，并将会员体系扩展为三级以适配更多场景。

## 对开发的影响

1. 用户表需预留 `user_level` 字段（FREE / MEMBER / PRO），所有功能权限校验统一通过权限中心接口判断，禁止硬编码判断等级。
2. 微信登录需在微信小程序端与 PC 端分别实现：小程序端调用 wx.login()，PC 端使用微信扫码登录。
3. 同一用户允许绑定多个登录方式（邮箱 + 手机 + 微信），通过统一用户 ID 关联。
4. 登录接口需支持 OAuth 2.0 标准流程，为后续第三方登录扩展（如 GitHub、Apple ID）预留接口。
5. 会员过期后，对应权益不可用但历史数据（如已生成的面试题）保留，用户可查看但不可新建。
