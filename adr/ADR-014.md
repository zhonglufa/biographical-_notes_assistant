# ADR-014 通知渠道

## 状态

已采纳

## 背景

用户需要实时了解投递进展、面试邀约、HR 回复等关键信息，及时的通知是提升用户活跃度与留存率的关键手段。不同场景下通知的时效性、正式程度、触达率要求不同，需要一套覆盖全场景的通知体系。

## 决策

采用**四类通知渠道**组合，按场景区分使用：

| 渠道 | 适用场景 | 特点 |
|------|----------|------|
| WebSocket 实时推送 | 站内通知（投递状态变更、HR 查看简历、系统消息） | 实时性好、免费 |
| 邮件通知 | 面试邀约详情、每周推荐报告、账号安全通知 | 正式、可存档 |
| 短信通知 | 面试确认、投递失败通知、验证码 | 紧急、触达率高 |
| 微信模板消息 | 小程序内投递进展、面试提醒 | 微信生态触达率高 |

## 理由

1. **全场景覆盖**：站内实时推送保证用户在线时的即时体验；邮件用于正式通知可存档；短信用于紧急通知确保触达；微信模板消息利用微信生态每日触达用户。
2. **成本与效果平衡**：WebSocket 和微信模板消息近乎免费，邮件成本极低，仅短信有一定成本但仅在关键场景使用，整体可控。
3. **参考行业通行做法**：BOSS 直聘同时使用 App Push、短信、邮件三通道，重要通知多通道同步发送，确保用户不遗漏。

## 候选方案

1. **仅站内通知**：优点是零成本；缺点是用户离线时完全无法收到通知，触达率极低，核心场景（如面试邀约）不可接受。
2. **仅邮件通知**：优点是成本低、可存档；缺点是延迟高（用户可能数小时才查看邮件），且垃圾邮件过滤可能导致用户收不到。

## 竞品参考

BOSS 直聘的通知体系采用 App Push + 短信 + 邮件多通道并行，重要通知（如面试邀约）同时走所有通道，确保用户不遗漏。本项目微信小程序场景增加了微信模板消息替代 App Push。

## 对开发的影响

1. 通知系统需抽象为统一的通知中心模块，各业务模块只需调用通知中心接口并指定通道与模板，不做重复实现。
2. 每条通知必须记录发送状态（成功/失败/已读），便于后续统计与补发。
3. 用户必须在设置页面可以自主选择关闭/开启各渠道的通知（如：允许关闭邮件通知，但短信通知不可关闭）。
4. WebSocket 连接需在 Redis 中维护用户在线状态，离线用户的消息落库，下次上线时同步推送。
5. 邮件与短信使用第三方服务商（如阿里云邮件推送、短信服务），需封装适配层，避免厂商锁定。
