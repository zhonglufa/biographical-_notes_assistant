# ADR-010 前端技术栈

## 状态

已采纳

## 背景

产品需要覆盖多端场景：PC 端管理后台与核心操作页面、移动端 H5 页面、以及流量获取与触达效率最高的微信小程序。需要一种能够在多端间最大化代码复用的技术方案，同时兼顾国内生态成熟度与团队技能。

## 决策

采用 **Vue 3 + Element Plus + uni-app** 技术栈：

- **Vue 3 + Element Plus**：PC 端管理后台（用户管理、投递看板、数据统计、简历编辑等复杂交互页面）。
- **uni-app**：H5 移动端 + 微信小程序，一套代码产出多端。

## 理由

1. **Vue 3 国内生态成熟**：Vue 在国内开发者受众最广，社区文档、组件库、技术问答资源丰富，招聘与接手成本低。
2. **Element Plus 中后台组件丰富**：表格、表单、弹窗、筛选器等组件一应俱全，大幅提升 PC 端开发效率。
3. **uni-app 多端发布**：一套代码输出 H5 与微信小程序，有效降低移动端开发与维护成本，适合独立开发者。
4. **国内竞品已验证**：超级简历使用 uni-app 覆盖多端，牛客使用 Vue 技术栈，证明该技术选型在同类产品中可行。

## 候选方案

1. **React + Ant Design（PC）+ React Native / Taro（移动端）**：优点是 React 国际化程度高；缺点是 Ant Design 国内中后台生态弱于 Element Plus，团队学习成本高，国内招聘 React 开发者相对难度大。
2. **Flutter（全端）**：优点是跨平台统一、性能好；缺点是学习成本高、与 Web 生态割裂（无法直接复用 Web 组件库）、简历编辑等富文本场景在 Flutter 中体验不佳。

## 竞品参考

超级简历（成功的一站式简历产品）使用 uni-app 覆盖多端；牛客网使用 Vue 技术栈。本项目参考其技术选型。

## 对开发的影响

1. PC 端与移动端共用同一套 API 接口，由后端统一适配，前端不做多端适配逻辑。
2. 移动端使用 uni-app 开发时，需注意区分 H5 与小程序的环境差异，使用条件编译处理平台特有逻辑。
3. 所有 UI 组件需遵循统一的设计规范（颜色、间距、字体），确保多端视觉一致性。
4. 内部工具与原型先用 HTML 输出，落地后再转化为 Vue/uni-app 组件。
5. 避免在 uni-app 中引入复杂原生插件，优先使用 Vue 生态兼容方案，降低跨平台兼容问题。
