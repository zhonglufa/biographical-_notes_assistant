# ADR-013 智能推荐冷启动

## 状态

已采纳

## 背景

岗位推荐是产品的核心价值功能之一。新用户注册后，系统没有任何用户行为数据（浏览、收藏、投递、忽略），无法使用协同过滤或深度学习模型进行个性化推荐。冷启动期推荐质量直接决定用户留存，需要一种无需用户行为数据即可运行、并随用户使用逐步精准的推荐方案。

## 决策

采用**规则引擎兜底 + 逐步迭代模型**的两阶段推荐策略：

1. **冷启动期（无行为数据）**：基于用户简历内容（技能标签、学校、专业、期望城市、期望岗位）做关键词匹配推荐。同时提供"热门岗位"模板作为兜底，展示近期投递量最高的岗位。
2. **温启动期（有初步行为数据）**：收集用户的收藏、投递、忽略反馈，逐步迭代内容推荐模型，将用户行为信号（权重）加入推荐排序。

## 理由

1. **无需用户行为数据即可推荐**：规则引擎仅依赖用户填写的简历信息，新用户注册完善简历后即可获得推荐，零冷启动等待。
2. **随使用逐步精准**：用户行为数据积累后，推荐排序从规则引擎逐步过渡到模型驱动，用户体验自然提升。
3. **"热门岗位"模板兜底**：即使简历信息不完整，用户仍可浏览热门岗位，保证推荐页面不空。
4. **实现简单、可迭代**：规则引擎实现成本低，可在 MVP 阶段快速上线，后续逐步引入 ML 模型优化。

## 候选方案

1. **纯协同过滤（用户-岗位矩阵）**：优点是推荐结果个性化强；缺点是冷启动问题严重，新用户无行为数据时无法推荐，推荐列表为空，体验差。
2. **纯内容推荐（仅基于简历标签匹配）**：优点是简单可执行；缺点是无法个性化排序，所有用户推荐结果趋同，无法根据用户反馈优化。

## 竞品参考

LinkedIn 早期推荐系统以规则引擎为主（基于技能、行业、职位等维度做匹配），在积累大量用户行为数据后逐步加入 ML 模型，最终形成混合推荐架构。本案采用相同的演进路径。

## 对开发的影响

1. 规则引擎需维护一套可配置的匹配权重表（技能匹配权重、学校匹配权重、城市匹配权重等），支持运营动态调整。
2. 用户行为数据（收藏、投递、忽略、查看详情）必须全量埋点并入库，为后续模型迭代提供数据基础。
3. 推荐接口需支持分页，冷启动期每次返回至少 10 条推荐结果，保证页面不空。
4. 用户忽略某个岗位后，30 天内不再推荐相同岗位，且降低该岗位所属企业的其他岗位排序。
5. 推荐结果需附带"推荐理由"（如"该岗位要求 Android 与你的 3 年经验匹配"），让用户感知推荐逻辑。
