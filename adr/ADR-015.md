# ADR-015 监控运维体系

## 状态

已采纳

## 背景

生产环境上线后，需要实时了解系统健康状态：服务是否存活、接口响应是否正常、数据库连接池是否充足、资源使用是否达到瓶颈。独立开发者无法投入全天候人工值守，需要一套自动化、可告警的监控运维体系。

## 决策

采用 **Prometheus + Grafana + Loki + Alertmanager** 开源监控组合：

- **Prometheus**：指标采集与存储，采集服务 JVM 指标、接口响应时间、QPS、错误率、系统资源利用率。
- **Grafana**：可视化面板，展示系统总览、各服务健康状态、数据库与 Redis 连接情况。
- **Loki**：日志聚合，统一收集 Java 与 Python 服务的日志，支持按 trace_id 检索。
- **Alertmanager**：告警管理，设置关键指标的告警规则（如接口错误率 > 5%、CPU > 80%），通过邮件/钉钉/企业微信通知。

## 理由

1. **开源免费**：全套组件均为开源项目，无需 license 费用，对独立开发者友好。
2. **云原生标准**：Prometheus + Grafana 是云原生监控事实标准，社区活跃、文档丰富、问题排查资料多。
3. **Docker 一键部署**：整套体系可通过 docker-compose 一键启动，运维成本低。
4. **日志与指标联动**：Loki 与 Prometheus 共享标签，可在 Grafana 中从"指标异常"直接跳转到"关联日志"，快速定位问题根因。

## 候选方案

1. **Datadog**：优点是功能全面、开箱即用；缺点是成本高昂，对独立开发者无法承受（月费数百至数千美元）。
2. **SkyWalking**：优点是 APM 能力强、分布式追踪完善；缺点是偏重 APM 场景，指标与日志能力弱于 Prometheus+Loki，且运维复杂度高。

## 竞品参考

（该决策主要基于开源技术栈与成本因素的工程判断。多数中小型 SaaS 团队采用 Prometheus + Grafana 组合，云原生社区的实践验证充分。）

## 对开发的影响

1. Java 服务必须引入 Micrometer 暴露 Prometheus 指标，Spring Boot Actuator 自动集成。
2. Python 服务必须引入 Prometheus Client 库，手动暴露关键业务指标。
3. 所有日志必须包含 `trace_id`，便于 Loki 按请求链路检索。
4. 关键告警规则（服务宕机、错误率突增、慢查询）必须在 Alertmanager 中配置，并绑定通知渠道。
5. 监控面板（Dashboard）需在 Grafana 中至少配置：系统总览、JVM 概览、接口响应时间分布、数据库与 Redis 连接数、错误率趋势。
