# ADR-018 安全与风控

## 状态

已采纳

## 背景

产品涉及两类敏感数据：一是用户个人简历（包含姓名、手机号、教育经历等隐私信息）；二是用户存储的招聘平台账号密码（用于自动化投递）。同时，自动化投递行为可能触发招聘平台的风控机制，需要多层次的防御策略。安全与风控是产品的底线，必须在设计阶段充分规划。

## 决策

### 安全策略

| 技术 | 用途 |
|------|------|
| BCrypt | 密码哈希存储，所有用户密码使用 BCrypt 加盐哈希，不存储明文 |
| JWT RS256 | 无状态令牌，使用 RSA 非对称签名，令牌不存储在服务端 |
| AES-256-GCM | 招聘平台账号密码加密存储，密钥独立管理，与业务数据分离 |
| Sentinel | 限流组件，按接口、用户、IP 多维度限流 |
| X-Idempotent-Key | 幂等键机制，防止投递、支付等关键操作重复提交 |

### 风控策略（三阶段）

| 阶段 | 措施 |
|------|------|
| 第一阶段 | 浏览器指纹随机化：每次启动浏览器时随机化指纹参数（User-Agent、Canvas、WebGL、时区等） |
| 第二阶段 | 代理 IP 池：按城市分配代理 IP，每次投递切换 IP，模拟真实用户分布 |
| 第三阶段 | 日投递上限控制：单账号每日投递不超过 150 次，超过后自动暂停 |

## 理由

1. **多层次安全纵深防御**：从密码存储、令牌签发、敏感数据加密到接口限流，构建多层防线，单层突破不会导致全盘泄露。
2. **AES-GCM 加密敏感凭证**：招聘平台账号密码是最高敏感数据，使用 AES-256-GCM 认证加密确保数据的机密性与完整性。
3. **三阶段风控逐层防御**：浏览器指纹随机化规避自动化检测，代理 IP 池规避 IP 频率检测，日投递上限兜底，三者叠加可有效降低封号风险。

## 对开发的影响

1. 所有密码必须使用 BCrypt 哈希，且哈希成本因子（strength factor）不低于 10，禁止使用 MD5/SHA1 等弱哈希算法。
2. JWT 令牌的 RSA 私钥必须存储在安全配置中心（如阿里云 KMS），禁止硬编码在代码库或配置文件中。
3. 加密招聘平台账号密码的 AES-256-GCM 密钥必须与业务数据库分离存储，定期轮换。
4. 所有接口必须接入 Sentinel 限流，关键接口（登录、投递提交、支付）限流阈值需单独配置，禁止使用默认值。
5. 风控模块需支持规则动态配置（通过数据库或配置中心），可在不重启服务的情况下调整投递上限、IP 切换频率等参数。
