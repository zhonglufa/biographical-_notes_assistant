# ADR-002 技术栈选型

## 状态

已采纳

## 背景

产品同时包含两类性质差异很大的能力：一类是典型的业务系统能力（用户、订单、投递管理、数据统计），要求稳定、事务性强、生态成熟；另一类是 AI 能力（简历优化、模拟面试、自动化投递），高度依赖 Python 生态的机器学习库、爬虫框架和浏览器自动化工具。单一技术栈难以同时满足两方面的需求，需要明确各自的选型。

## 决策

采用**双语言异构架构**：

- **Java Spring Boot 3.x**：承载业务服务，包括用户体系、简历管理、投递状态机、会员与支付、通知推送等核心业务逻辑。
- **Python FastAPI**：承载 AI/自动化引擎，包括 LLM 调用与提示词编排、简历优化、模拟面试、岗位数据采集爬虫、Playwright 浏览器自动化投递。
- **ORM：MyBatis-Plus 3.5.7（Spring Boot 3 starter）**：承载 Java 业务侧持久化（详见文末「ORM 选型补充说明」）。早期 ADR-002 未指定 ORM，2026-08-18 由用户（Java 工程师）拍板由未真正落地的 Spring Data JPA 改为 MyBatis-Plus；持久层 `XRepository extends BaseMapper<X>` 并以 `default` 方法保留 JPA 风格签名，服务/控制器层零改动。

两套服务通过 RESTful API 与消息队列解耦协作。

## 理由

1. **Java 生态成熟**：Spring Boot 3.x 在企业级业务系统、事务管理、安全框架、运维监控方面生态完善，长期维护成本低。
2. **Python 生态适配 AI 场景**：PyTorch、LangChain、Playwright、Scrapy 等 AI 与自动化库均为 Python 原生，开发效率最高。
3. **职责边界清晰**：业务与 AI 引擎解耦，各自独立迭代、独立伸缩，互不阻塞。
4. **人才匹配**：国内 Java 与 Python 开发者供给充足，后续招聘容易。

## 候选方案

1. **全 Java（Spring Boot + DeepLearning4J / Java 爬虫）**：优点是统一技术栈、组件复用；缺点是 Java 的 AI/爬虫生态明显弱于 Python，DL4J 生态不活跃，Playwright Java 版自动化能力受限，开发成本高。
2. **全 Python（FastAPI 承载全部业务）**：优点是语言统一；缺点是 Python 在高并发业务接口、事务型业务系统上存在性能瓶颈，且长期维护企业级业务代码的工程化能力弱于 Java。

## 竞品参考

多数竞品采用前后端分离架构，且普遍将 AI 相关能力独立为 Python 服务（如简历优化、面试模拟模块），业务主站使用 Java/Go 等静态语言。本项目参考该成熟实践，将 AI 部分独立为 Python 服务。

## 对开发的影响

1. Java 服务与 Python 服务之间只通过 API 契约和消息队列通信，禁止任何形式的数据库直连共享。
2. 双服务需统一日志、监控、链路追踪标准，便于问题定位。
3. AI 引擎的接口需设计为异步任务模式（耗时任务返回 task_id），避免阻塞业务主链路。
4. 两个服务都必须编写独立的单元测试与集成测试，CI 流水线分别构建部署。
5. 共享的领域模型（如岗位、简历数据结构）需在 API 契约中统一定义，控制重复实现导致的漂移。

## ORM 选型补充说明（2026-08-18 增补）

ADR-002 初版仅规定「Java Spring Boot 3.x」，未指定 ORM。2026-08-18 用户（Java 工程师）拍板采用 **MyBatis-Plus 3.5.7**（Spring Boot 3 starter），替代此前设计/代码中未真正落地的 Spring Data JPA。

**持久化约定**：

- 持久层接口 `XRepository extends BaseMapper<X>`，并以 `default` 方法保留 JPA 风格方法签名（`findById` / `save` / `existsById` / `findAll` / `count` 等），使服务层与控制器层调用零改动（仅改 `extends` 子句与导入）。
- 分页通过 `PaginationInnerInterceptor(DbType.MYSQL)` 实现；测试环境 H2 以 `MODE=MySQL` 运行，LIMIT/OFFSET 方言与 MySQL 一致，可共用。
- `@MapperScan("com.resumeai.module.*.repository")` 仅扫描各模块 repository 包，避免误扫 service / client 等非 Mapper 接口。
- 实体用 `@TableName` / `@TableId` / `@TableField` **显式映射列名**——MyBatis-Plus 不会像 Hibernate 那样自动做驼峰→下划线转换，每个非 `@TableId` 字段都需 `@TableField("snake_col")`。
- 生产 schema 仍由 Flyway（`V1`–`V9`）管理；测试 schema 由 `src/test/resources/db/migration-test/`（H2 兼容副本，已剥离 `ENGINE/CHARSET/COLLATE`、`JSON→TEXT`、`UNSIGNED`）提供，保证 `mvn test` 在无 MySQL 实例时仍可建表。
