# ADR-005 岗位数据采集策略

## 状态

已采纳

## 背景

产品的核心价值之一是聚合校招/社招岗位信息，但独立开发者无法与 BOSS 直聘、智联招聘等大型招聘平台达成数据合作，需要自建数据源。数据源的选择直接决定数据质量、法律风险与采集成本。

## 决策

自建采集体系，覆盖以下三类合法、低风险的数据源：

1. **企业微信公众号**：采集企业发布的校招/社招文章（布局、岗位、投递入口）。
2. **企业官网招聘页**：如 zhiye.com、hotjob.cn、mokahr.com 等企业招聘系统页面。
3. **高校就业网**：高校就业指导中心发布的校招信息。

**明确不爬取** BOSS 直聘、智联招聘、前程无忧等竞品平台。

## 理由

1. **offerstar.cn 已验证数据来源**：其约 90% 的岗位数据来源于微信公众号文章，证明该路径可行且数据量充足。
2. **微信公号爬取法律风险低**：企业主动公开发布的文章属于公开信息，规避了招聘平台用户协议与数据权益纠纷。
3. **企业官网无防盗链**：企业招聘官网（Moka、北森等系统页面）无严格反爬，页面结构标准，解析成本低。
4. **高校就业网信息权威**：校招信息源头可靠，且为高校公开数据，合规性较好。

## 候选方案

1. **与招聘平台合作获取数据**：优点是数据全面权威；缺点是对独立开发者而言几乎不可能达成，且存在平台政策壁垒。
2. **购买第三方数据服务**：优点是省去采集开发；缺点是成本高、数据时效性差、质量不可控，独立开发者难以承担。

## 竞品参考

offerstar.cn 以微信公众号为主要数据来源，占其数据总量约 90%；本项目数据源策略与其一致，并补充企业官网与高校就业网作为增强。

## 对开发的影响

1. 采集模块必须遵守 robots 协议与目标网站服务条款，禁止对单一站点高频请求，必须具备限速与重试退避机制。
2. 采集数据必须记录来源 URL 与采集时间，为后续合规审计与数据溯源留痕。
3. 采集任务统一走 RabbitMQ 队列异步执行，支持断点续采与失败重试。
4. 相同岗位跨来源去重：以"企业 + 岗位名称 + 城市 + 发布时间"为去重键。
5. 明确禁止扩展采集范围至 BOSS/智联/前程无忧等平台，代码评审时作为红线检查项。
