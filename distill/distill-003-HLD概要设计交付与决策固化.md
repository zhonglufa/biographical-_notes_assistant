#### 5.2 方法论标准（v3.0 核心变更）
1. **制图方法论**：采用 C4 模型（System Context → Container → Component → Code），一图一层次，禁止多层混合。时序图遵循 UML 2.5 规范，必须包含激活条、同步/异步箭头区分、生命线。
2. **风格规范**：白底 `#ffffff`，应用容器蓝 `#1a73e8`/`#e8f4fd`，数据存储绿 `#22c55e`/`#f0fdf4`，消息中间件红 `#ef4444`/`#fef2f2`，基础设施灰 `#9ca3af`/`#f8f9fa`，参与者黄 `#eab308`/`#fefce8`；阴影用 feDropShadow。
3. **可读性四原则**（v2.0 继承，延续至白底风格）：
   - **原则 1：连线不穿卡**——所有连线必须从卡片边缘出发/结束，路径只能走卡片之间的空隙（corridor 走廊）。
   - **原则 2：标注带底板**——所有连线上的文字标注必须带背景面板，确保文字不被底纹淹没。
   - **原则 3：虚线加粗加对比**——宽度 ≥1.8，`dasharray="7,5"`，高对比色。
   - **原则 4：命名一眼看懂**——禁止领域术语，全改中文通俗名，必要时加小字副说明。
4. **嵌入方式**：SVG 保存为独立文件至 `design/figures/`，Markdown 用 `![图说明](figures/xxx.svg)` 图片引用嵌入。
5. **命名规范**：`fig-<层级>-<主题>.svg`，C1/C2 图以"C1""C2"为前缀，业务图保持原编号（fig-2-2-apply-flow 等）。

#### 5.4 调研依据（v3.0 新增）
- 用户指出"没掌握软件工程设计作图的方法论"后，追加调研：
  - C4 模型（Simon Brown）——《Software Architecture for Developers》，一图一层次，像地图缩放
  - UML 2.5 规范（OMG 标准）——14 种标准图，激活条/同步异步箭头/生命线为时序图强制要素
  - 4+1 视图模型（Philippe Kruchten）——逻辑/开发/进程/物理 + 场景
- 发现 v2.0 根本问题：前 6 张图混用多层抽象（架构图同时包含系统和组件），时序图缺少激活条和箭头区分，部署图缺少节点概念。v3.0 按 C4 + UML 重新设计，彻底解决。
