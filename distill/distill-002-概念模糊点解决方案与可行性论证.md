# 蒸馏记录 002：概念模糊点解决方案与可行性论证

## 会话时间
2026-08-13

## 讨论背景
PRD 补充（角色权限矩阵 + 全局异常场景）完成后，用户提出两个质疑：
1. 是否存在概念模糊问题？——需要实际检查 PRD
2. 如何说服项目的可行性与可落地性？——不回避风险地论证

## 关键结论

### 一、概念模糊检查结果（4 个真模糊点）

| # | 模糊点 | 严重度 | 解决方案 |
|---|--------|-------|---------|
| 1 | 摄像头用途无定义（说"含摄像头"但评估只用文本） | 中 | 降级为本地自我视角参考，不评估不录制不上传 |
| 2 | "HR 已查看"状态如何感知（平台无 Webhook） | 高 | 定义为尽力感知（Best-Effort）+ 轮询双通道 + 不构成硬依赖 |
| 3 | 高级版"优先支持"无操作定义 | 中 | SLA 化：48h 响应 / beta 优先 / 新平台优先队列 |
| 4 | 高校模板"覆盖 80%"无数值支撑 | 低 | 标注为估算值 |

### 二、可行性论证方法（说服框架）

核心立场：**不承诺"没问题"（不诚实），而是把风险变成可验证的决策点**。

已验证能力（用户现有代码，约 60% 关键路径）：
- get_jobs Java 项目：5 平台爬虫（BOSS/智联/51/拉勾/猎聘），Playwright+Selenium
- LLM 集成已上线（AiConfig/AiService/AiFilter 过滤岗位）
- Python 扫描器 daily_job_scanner 在跑

高风险点（集中在"投递写操作"）：
- 自动投递表单/验证码/风控（比抓取难一个量级）
- HR 状态感知（无 Webhook 只能轮询）
- 封号风险

落地保障 4 道机制：
1. PoC 先行：写正式代码前，1-2 周单平台（BOSS）投递闭环验证，结果决定投递模式
2. 人机协同兜底：验证码/滑块时人工接手（浏览器自动化天然支持）
3. 适配器抽象隔离：PlatformAdapter 接口隔离单平台风险
4. 分阶段里程碑：M1 数据链路 → M2 投递闭环 → M3 AI 能力 → M4 联动付费，每段可验证

### 三、3 个模糊点的最终方案（已写入 PRD）

1. **摄像头**：模块 6 增加"摄像头定义"段落——本地画中画，不参与评估、不录制、不上传，权限被拒不影响功能
2. **HR 状态感知**：模块 7 改写联动数据流——面试题"生成中 → 可查看"（不依赖 HR 事件）；HR 查看感知改为可选增强通知；状态机允许 unknown；适配器接口定义 `getApplicationStatus()` 轮询通道
3. **优先支持**：模块 8 权限矩阵后增加 SLA 定义——48h 响应 / beta 优先体验 / 新平台优先队列
