# 【机制】问题分析自动蒸馏 SOP

> 固化自 distill-004 的用户要求："看问题+分析的工作过程要自动化记录"。
> 本文件是项目级规则，后续所有评审/分析类工作默认执行，无需用户重复强调。

## 1. 触发条件（满足任一即自动蒸馏）
- 对**现有交付物**做评审/找问题/挑错（如 PRD/HLD/LLD/代码/原型）。
- 对**某个设计决策**做利弊分析、风险剖析、可行性论证。
- 用户明确说"评审""你怎么看""有没有问题""分析一下"。
- 发现文档/代码中的**矛盾、缺口、反模式**。

> 说明：纯正向创作（从零写文档、画图、写代码）按对应产物归档，不必强套本条；但其间的**关键权衡与决策**仍应落 distill（见第 4 条"衍生决策"）。

## 2. 落档规则
- **目录**：`E:\简历\resume-ai-prod\distill\`
- **命名**：`distill-NNN-<主题>.md`，NNN 取现有最大编号 +1（当前最大 004）。
- **编号自增**：每次写前用 `ls distill/` 确认最大编号，避免冲突/覆盖。
- **语言**：中文，延续既有 distill 字段结构（见第 3 条）。

## 3. 标准字段（与 distill-001~004 一致）
```
# 蒸馏记录 NNN：<一句话主题>

## 会话时间
YYYY-MM-DD

## 讨论背景
<为什么做这次分析、谁发起、什么对象>

## 关键结论
### 一、🔴 必须修的硬伤（如有）
### 二、🟠 重点风险 / 缺口
### 三、🟢 做得好的（可选）
### 四、待办决策
<每条含问题、证据位置、影响/建议，用表格更清晰>

## 衍生决策
<本次固化下来的新规则/偏好/判断>

## 影响范围
<影响哪些文件、是否阻塞后续阶段>

## 关联文档
<被评审对象 + 上下游文档 + ADR>
```

## 4. 分级标签约定
- 🔴 硬伤：文档自我矛盾 / 地基级未决 / 容量算不平（进 LLD 前必须闭环）。
- 🟠 风险/缺口：影响落地但不致命，需补设计。
- 🟢 亮点：保留项，评审时明确点出，避免后续被误改。

## 5. 自动化的边界
- "自动"指**助手主动执行**：完成分析后当场生成 distill 条目，不询问"要不要记"。
- 用户偏好（来自 distill-003/004）：直接给结论与决策，**不要反复确认**。
- 例外：若评审对象尚未存在或路径不明，先确认对象再评，不臆造。

## 6. 与既有机制的关系
- 本 SOP 与 distill-003 的"图交付标准"、各 ADR 并行不悖，互不替代。
- distill 体系定位：PRD/ADR 是决策依据，HLD/LLD 是设计产物，**distill 是"评审与分析过程"的留痕**，三者闭环。
