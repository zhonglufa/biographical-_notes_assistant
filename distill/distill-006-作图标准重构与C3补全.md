## 关键结论

### 一、原文档缺点识别

| 缺点 | 表现 | 影响 |
|------|------|------|
| **体积过大** | 117KB 单文件,章节嵌套深 | 阅读/编辑/审查体验差 |
| **图类型覆盖不全** | 缺少 C3 组件图、UML 类图、活动图、状态机图等专项 | 团队需要时无章可循 |
| **规则分散** | ST-1~14 散落在不同章节,无统一索引 | 跨图类型引用困难 |
| **缺乏自动化** | 标准靠人工 review,易遗漏 | 评审成本高,违规难以拦截 |
| **缺可执行性** | 仅有描述性规则,无可校验的脚本 | 标准执行率低 |

### 三、C3 组件图规范核心要点 (§3.9)

**决策目标**: 展开 C2 中某个容器,展示其内部组件结构
**C4 层级纪律**:
- 只允许出现目标容器内的组件 + 接口 + 依赖
- 禁止出现: 其他容器内部细节 / 类名包名 / 协议:端口
- 必选: 目标容器边界(蓝色虚线大矩形)

**元素完备性**:
- ✅ 目标容器边界(虚线大矩形 + `[Container: 容器名]` 标签)
- ✅ 组件(浅蓝填充矩形 + 业务能力命名)
- ✅ 灰盒(外部容器/数据库用 #F3F4F6 + #9CA3AF 灰盒表示)
- ✅ lollipop 接口标记(对外暴露的关键接口)
- ❌ 禁止: 协议:端口(应回 C2)

**关键反模式**:
1. **C3 降级为类图** —— 列出所有类/方法,违反单一抽象层级
2. **C3 越权标协议** —— 写 `gRPC:50051`,应回 C2
3. **C3 多容器混画** —— 一张 C3 画多个容器
4. **技术后缀命名** —— `Service` / `Manager` / `Util`,应改业务能力名

**审查清单**: 3.9.1 ~ 3.9.15 共 15 项

### 四、自动化校验脚本 lint-svg.cjs

**入口**: `design/figures/lint-svg.cjs` (~20KB, 566 → 700+ 行)

**检查维度**:
| 规则 | 范围 | 严重度 |
|------|------|--------|
| ST-10 | 垂直线文字不居中 | 错误 |
| ST-11 | 水平线文字居中 | 警告 |
| ST-13 | 文字与线不交叉 | 错误 |
| ST-14 | 每条线只有一个标注 | 错误 |
| STROKE-WIDTH | 线宽 1/1.5/2/2.5/3 | 警告 |
| COLOR-PALETTE | 颜色色板一致性 | 警告 |
| FONT-SIZE | 字号 9/10/11/13/14/16 | 警告 |
| ASPECT-RATIO | viewBox 4:3 ~ 2:1 | 警告 |
| **C3-PROTOCOL** | C3 禁止协议:端口 | **错误** |
| **C3-CONTAINER-BOUNDARY** | 目标容器虚线边界 | 警告 |
| **C3-GRAY-BOX** | 灰盒样式规范 | 警告 |
| **C3-COMPONENT-COUNT** | 组件数 ≤ 12 | 错误 |
| **C3-INTERFACE-MARKER** | lollipop 接口标记 | 警告 |

**CLI 用法**:
```bash
node lint-svg.cjs <file.svg> [file2.svg ...]
node lint-svg.cjs --dir <directory>           # 批量校验
node lint-svg.cjs --json <file.svg>           # JSON 输出
node lint-svg.cjs --strict <file.svg>         # 严格模式
```

**C3 自动识别**: 文件名包含 `c3` 或 `c3-component` 即触发 C3 专项校验

## 关键决策

| 决策 | 理由 |
|------|------|
| 按"一图一文件"拆分,不做合并章节 | 便于针对性编辑/引用/审查 |
| C3 单独成节,不放 C2 内 | C2/C3 抽象层级不同,需要独立规范 |
| lint-svg.cjs 放在 `figures/` 子目录 | 与 SVG 文件同目录,便于批量校验 |
| C3 自动识别靠文件名 | 避免在 SVG 内部加 metadata,保持纯净 |
| 协议:端口在 C3 强制禁用 | 防止 C3 越权,保持 C4 层级纪律 |
