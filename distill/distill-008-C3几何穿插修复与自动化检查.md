# 蒸馏记录 008：C3 几何穿插修复 + geometry-check 自动化

## 会话时间
2026-08-15

## 讨论背景

用户反馈"fig-c3-component.svg 这张图通过不了啊,线问题,穿插容器了"。

**问题严重度**: v1.0 C3 组件图有 5 处 P0 几何穿插 + 4 处 P1 斜线违规,但 lint-svg.ps1 的 9 项规则全部 PASS — **说明自动化检查有盲区**。

## 根因分析

| 维度 | 现状 | 缺口 |
|------|------|------|
| 通用规则 (STROKE-WIDTH / COLOR / FONT-SIZE / ASPECT) | ✅ 4/4 | 无 |
| C3 专项 (PROTOCOL / BOUNDARY / GRAY-BOX / COUNT / INTERFACE) | ✅ 5/5 | 无 |
| **几何穿插** | ❌ **完全缺失** | **0 规则** |
| 斜线检测 | ❌ 缺失 | 0 规则 |
| 线-线交叉 | ❌ 缺失 | 0 规则 |

**核心问题**: lint-svg.cjs 和 lint-svg.ps1 都基于 SVGParser 解析**元素级**属性(颜色/字号/线宽),**不解析 path d 属性的几何段**,所以检测不到线-容器穿插、线-线交叉、斜线违规。

## 关键决策

| 决策 | 理由 |
|------|------|
| 编写独立的 geometry-check.ps1 而非扩展 lint-svg.ps1 | 几何检查逻辑独立, 路径段解析与属性解析是不同关注点, 单一职责 |
| 几何检查只针对 C3 命名文件触发 | C1/C2/时序图/ER 几何规则不同, 后续可扩展 |
| 零容忍原则: 任何穿插都算 FAIL | 比 lint 警告更严, 因为穿插是 P0 视觉错误 |
| 端点接触算 OK, 穿越算 FAIL | 端点接触是合法"连接到容器" |
| 跳过 `<defs>` 内的 path | marker 三角形的 d 段是斜线, 不算违规 |
| 跳过目标容器虚线边界 rect | 虚线边界是画布, 允许线穿越 |

## 关键设计模式 (从修复提取)

### 业务层 → 外部灰盒的统一路由
```
源(x_s, 340) → 垂直 60-80px → 水平到 (x_ch, y_h) → 垂直到 (x_ch, y_target) → 水平 60px 进灰盒
```
- 起点 y=340: 业务层下边界 (容器外)
- 拐点 x=760-780: 目标容器右边界 (x=750) 外 10-30px
- 终点 x=820: 灰盒左边界
- 通道 70px (750-820) 供垂直段通过

### 业务层 → 数据层跨列路由
```
源(x_s, 340) → 垂直 40px → 水平到 (x_t, 380) → 垂直 40px 进数据层
```
- 起点 y=340: 业务层下边界
- 通道 y=380: 业务层 (270-340) 与数据层 (420-490) 之间的间隙
- 终点 y=420: 数据层上边界

## 教训 (写入 project_memory)

### 规则
- 几何检查必须独立于属性检查, 路径段解析是必需能力
- 任何"视觉正确性"规则都必须有自动化测试覆盖
- C3/C2 等含"线-容器"关系的图类型, 必须有几何穿插检查
- 零容忍原则: 视觉违规不应用 warning 级别, 应用 error 级别

### 反例
- 仅靠"颜色/字号/线宽"等属性检查, 无法保证视觉正确
- 手动 review C3 这类高密度连线图, 错误率 100% (本次就是漏掉了 5 处 P0)
