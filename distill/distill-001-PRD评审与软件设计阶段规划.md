# 蒸馏记录 001：PRD 评审与软件设计阶段规划

## 会话时间
2026-08-13

## 讨论背景
用户在完成 PRD 最终版和 23 个 ADR 后，对项目整体进行复盘，提出了 5 个核心问题：
1. PRD 最终版还有哪些信息没有考虑？
2. 原型图设计是否合理？
3. 软件开发生命周期中还缺少哪些交付文档？
4. 有没有做持久化蒸馏方便学习和跟进？
5. 如何确保整个过程形成闭环？

## 关键结论

### 1. PRD 缺失项
- 用户角色权限矩阵（管理员 vs 普通用户）
- 边界与异常状态覆盖不全（LLM 降级、浏览器实例池 OOM、支付失败等）
- 埋点缺少上报时机和属性字段定义
- 用户反馈闭环机制缺失

### 2. 原型评审结论
- 视觉优秀（暗色玻璃拟态 + 霓虹强调色），但覆盖不全
- 缺少移动端高保真原型、异常状态、新手引导、投递策略配置面板
- v2 和 v3 风格一致但有细微差异，需要 Design Token 统一定义

### 3. 软件设计阶段缺失文档（按优先级）
**P0（必须补齐才能开发）：**
- HLD（概要设计 / 技术架构文档）
- 数据库设计（ER 图 + 表结构）
- API 接口契约文档

**P1（开发过程中需要）：**
- LLD（详细设计 — 类图、时序图、算法）
- 前端组件设计规范（Design Token）

**P2（上线前需要）：**
- 测试计划
- 部署与运维手册
- 用户手册

### 4. 蒸馏机制决策
- 已有：ADR 23 个 + 快速蒸馏指南（第 1 级）
- 决定补充：distill/ 目录（对话蒸馏）+ 学习路径 + 三明治蒸馏体系
- 决定：每次关键对话后自动写入 distill 记录

### 5. 闭环机制设计
- 主循环：对话讨论 → 蒸馏记录 → 学习路径 → 文档产出 → 开发实施 → 结果验证 → 反思复盘 → 回到对话
- 单环反馈：发现偏差 → 直接修正 → 验证
- 双环学习：发现偏差 → 追问根本原因 → 改进流程/文档/机制 → 预防再发生

## 衍生决策
- 决定先做 HLD（概要设计），再依次做数据库设计 → API 契约 → LLD
- 决定用 html-report 技能交付设计文档（可交互 HTML 格式）
- 决定建立 distill/ 目录做对话持久化
- 确保每一步产出都有用户的 review 确认，不走下一步
