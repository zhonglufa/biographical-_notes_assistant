## §3.5 UML 部署图

#### 3.5.1 决策目标

| 问题 | 答案 |
|------|------|
| 支持什么决策 | 系统部署在哪些节点上？节点间如何通信？网络拓扑？ |
| 谁读 | DevOps、运维、架构师 |
| 决策后果 | 节点遗漏 → 部署失败；端口冲突 → 服务不可用 |

#### 3.5.2 元素完备性

| 元素 | 必须 | 说明 |
|------|------|------|
| 物理/虚拟节点 | ✅ | 服务器、容器、设备，用 3D 立方体或矩形表示 |
| 节点内部署单元 | ✅ | 每个节点中运行的容器/进程 |
| 通信路径 | ✅ | 节点间连接线，标注协议 : 端口 |
| 部署环境 | ✅ | 标注 dev/staging/prod 环境标识 |
| 外部系统 | ✅ | 外部依赖的部署位置（如第三方 API） |
| 图例 | ✅ | 节点/线型/颜色含义 |

#### 3.5.3 UML 语法

| 要素 | UML 规范 | SVG 实现 |
|------|---------|----------|
| 节点 | 3D 立方体 | `<path>` 绘制正等轴测图 |
| 部署单元 | 节点内矩形 | `<rect>` 在节点内部 |
| 通信路径 | 实线 | 标注协议 : 端口 |
| 依赖关系 | 虚线 | `stroke-dasharray` |
| 节点注解 | 附注框 | 节点旁 `<text>` |

#### 3.5.4 线条与间距

| 参数 | 标准值 | 说明 |
|------|--------|------|
| 节点间距 | 60px（最小） | 两个节点之间的最小距离 |
| 节点内元素间距 | 16px | 节点内部部署单元之间的间距 |
| 通信路径间距 | ≥ 14px | 并行路径的间距 |
| 节点大小 | 宽 220px × 高 160px（最小） | 节点立方体尺寸 |
| 3D 立方体深度 | 30px | 右面和下面的偏移量 |

| 元素 | 色值 | 字号 | 字重 |
|------|------|------|------|

#### 3.5.6 审查清单

```
□ 5.1  决策目标：部署图覆盖了哪些环境的拓扑？
□ 5.2  节点完备性：所有部署节点是否覆盖了全部容器？
□ 5.3  通信路径：每条路径是否标注了协议 : 端口？
□ 5.4  3D 节点：节点是否使用 3D 立方体表示？
□ 5.5  部署单元：每个节点内是否列出了运行的容器？
□ 5.6  环境标识：是否标注了 dev/staging/prod？
□ 5.7  颜色系统：节点正面/侧面颜色是否正确？
□ 5.8  线条规范：节点间距 ≥ 60px？路径间距 ≥ 14px？
□ 5.9  复杂度：节点 ≤ 10？路径 ≤ 15？
□ 5.10 元数据：是否完整？
□ 5.11 可追溯：节点/端口/环境是否对应 ADR？
□ 5.12 跨图一致：部署单元名称/端口/外部系统是否一致？
□ 5.13 图例：是否包含节点/线型/颜色含义？
□ 5.14 生命周期状态：是否正确？
```

#### 3.5.7 反模式

| 反模式 | 错误表现 | 正确做法 |
|--------|----------|----------|
| 容器当节点 | 把 C2 的容器图直接当部署图用 | 部署图必须展示物理/虚拟节点 |
| 无端口标注 | 通信路径只画线，不写端口号 | 每条路径标注 `HTTPS:443` 或 `gRPC:50051` |
| 缺少外部系统 | 没画第三方 API 的部署位置 | 必须画外部系统的节点 |
| 无环境区分 | 一张图混合 dev/prod 的节点 | 按环境拆分为多张图 |
| 节点内无部署单元 | 节点是空的，没写运行什么 | 每个节点内列出运行的容器/进程 |
| 3D 立方体不规范 | 3D 效果不一致，有些正面有些斜面 | 统一使用正等轴测图 |
