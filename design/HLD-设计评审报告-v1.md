# HLD 设计评审报告（v1）

> 评审对象：HLD v3.6（概要设计文档——AI 简历助手·自动投递与面试模拟）
> 上游基线：PRD v4.5 最终版
> 评审日期：2026-08-15
> 评审视角：资深架构师 / 技术评审（预 LLD 准入评审）
> 评审目标：判定 HLD v3.6 是否具备进入 LLD（详细设计）的设计成熟度，列出遗留风险与闭环条件。

---

## 0. 评审结论（Verdict）

**结论：有条件通过（Conditional Go）—— 可进入 LLD，但须在 LLD 启动前闭环 P1 项、并在各模块 LLD 前拍板 P2 项。**

理由：HLD v3.6 已完成"章节全覆盖 + 设计深度全覆盖 + 关键机制落地"三轮收口（B/G/T、TIER1/3、S1–S7），防漂移门禁双闸门实测全绿，PRD↔HLD 版本耦合一致（均 v4.5）。核心设计决策（本机 Agent 执行模型、反封号命门机制、可恢复/可审计/可验证删除、可演进架构）均已落成，达到预 LLD 准入标准。

**唯一阻断性问题是"文档可信度债"而非"设计缺陷"**：6 张架构图已在工作树删除且文档内引用全部失效，旧图仍描绘已被正文废弃的"服务端浏览器沙箱"模型，与正文"本机 Agent 执行"严重矛盾；§2 章节编号断裂（2.2→2.5）。这两项不修，评审者/下游 LLD 工程师看图与读 §2 会产生严重误解。

## 3. 进入 LLD 的建议路径（模块启动顺序）

基于"高风险前置 + 反封号命门 + 与图重绘强相关"三原则，**建议优先启动顺序**：

1. **【首选】本机 Agent + 投递执行模块 LLD**（§3.6/§3.7 + §6.14.1/§6.14.3/§6.14.4/§6.14.5）
   - 理由：① 是 PoC 验证核心（§8.2），决定产品能否成立；② 反封号命门（速率整形/验证码闭环/进程监督/配置签名）全在此；③ 与 P1-1 图重绘强相关——LLD 定了图才好重绘。
2. **数据链路 LLD**（§5 + M1）：采集器/岗位库/简历库/账号体系，岗位入库可查询、简历可编辑。
3. **状态机 + 幂等 LLD**（§3.4 + §6.13.2）：10 状态机、幂等键四元组、孤儿任务清扫。
4. **AI 编排 LLD**（§3.8/§3.9 + §7.1 降级链）：主备 LLM failover + 规则引擎兜底 + golden set 回归。
5. **商业化 LLD**（§3.10 + §7.5，须先闭环 P2-3 支付工作流）与 **规模化 LLD**（适配器市场）靠后。
