## 0. 范围与边界
- **本交付物必做**：护栏 3 = 轻量监控接入，聚合 4 项可度量指标 + 阈值告警（已实现于 `scaffold/src/monitor.py`）。
- **不引入 K8s / 重型可观测栈**：按用户 2026-08-17 运维取舍「K8s 现阶段不要」，监控用轻量方案（内存聚合 + 阈值告警），生产替换为 Prometheus/OTel（HLD §4.7）。
- 真实生产风险在业务层（封号/LLM成本/隐私），本监控直击这三类，比基础设施监控更该先有。

## 1. 监控指标（4 项 · 对齐护栏 3 定义）
| 指标 | 含义 | 数据来源 | DEMO 告警阈值 |
|---|---|---|---|
| `llm_cost_cents` | LLM 当日累计成本（分） | 成本护栏 `CostGuard` 记账 / `BudgetPolicy` | > 50000（¥500） |
| `ban_rate` | 封号率 = 封禁账号数 / 活跃账号数 | `BanTracker` | > 2% |
| `apply_success_rate` | 投递成功率 = 成功 / 总投递 | `ApplyLedger` | < 80% |
| `error_rate` | 接口错误率 = 错误请求 / 总请求 | B2-1 `MetricsSink` | > 5% |

## 2. 实现位置与接缝
- `scaffold/src/metrics.py`（`InMemoryMetrics` / `MetricsSink`）：B2-1 建立的指标接缝，`ServerApp.handle()` 每次请求记一条（端点/状态/成本）。
- `scaffold/src/monitor.py`
  - `MonitorThresholds`：4 项告警阈值（DEMO 默认，生产由运维配置）。
  - `BanTracker` / `ApplyLedger`：封号率 / 投递成功率计数。
  - `LightweightMonitor`：聚合 4 指标 → `snapshot()` 返回指标 + `alerts[]`（越阈值即列告警）。
- **演进路径**：本模块定义统一接缝与阈值语义；生产把 `InMemoryMetrics` 换成 Prometheus client、`LightweightMonitor.snapshot()` 改为 push gateway / expose `/metrics`，逻辑不变（contract-first：换传输不改规则）。

## 3. 与护栏 2 衔接
- `LightweightMonitor.llm_cost_cents` 由 `BudgetPolicy`/`CostGuard` 记账驱动；`llm_cost_over_cap` 告警与护栏 2 的 `CostGuardOpen` 形成「拦 + 曝」双保险。

## 4. 验证（已单测）

- 正常数据：无告警。
- 见 `scaffold/tests/test_monitor.py`，PASS，双闸门绿。

## 5. 封号率来源说明（诚实边界）
- 封号=平台账号风险，属业务层真实风险；脚手架中 `BanTracker` 为计数模型（活跃账号基数 + 封禁计数），真实封禁事件由本机 Agent / 平台回调上报（属用户本机 + 物理动作，循环不碰）。
- 监控只负责聚合与告警，不触发任何自动处置（避免误伤账号），处置建议推送用户（经 C2 通知/护栏 3 告警）。
