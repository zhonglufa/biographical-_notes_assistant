# 无障碍评估报告（§19 定级）

> 文档版本：2026-08-16 · v1.0 · 依据 HLD v3.32 / PRD v4.5
> 评审来源：设计评审清单 🔴 F-08 / C8（上线前必办清单 4）
> 定位：闭环评审清单「无障碍 §19 待定」一项；界定产品形态并定级 WCAG 目标。
> 关联：HLD §19（由「待定」升「已定级」）、风险登记表 R-14。

---

## 0. 产品形态界定

| 组件 | 形态 | 无障碍适用框架 |
|------|------|----------------|
| 本机 Agent（桌面守护进程） | 桌面应用（Win/macOS），含系统托盘 + 设置窗 + 投递确认弹窗 | OS 辅助功能 API（UIA / Accessibility API）+ 键盘可达 |
| Web 控制台 | 浏览器端：简历管理 / 策略配置 / 投递看板 / 日报 / 通知 | WCAG 2.1 |
| 通知 | 系统通知 + 应用内提示 | OS 通知无障碍规范 |

---

## 1. WCAG 定级结论

- **Web 控制台（对外发布部分）：目标 WCAG 2.1 AA**。理由：属面向公众的信息与服务界面，AA 为业界通行合规基线；若仅作者自用可降为 A，但公开发版按 AA。
- **本机 Agent 桌面端**：遵循 OS 辅助功能 API，保证键盘可达 + 屏幕阅读器可识别核心控件（投递确认、设置、状态）；不强制 WCAG 但参照 AA 交互原则。
- **通知**：遵循 OS 通知无障碍规范（不可过于频繁、可静音/关闭）。

---

## 2. 须适配界面清单（Web 控制台）

| 界面 | 关键适配点 | 验收准则（AA 摘录） |
|------|-----------|---------------------|
| 简历管理/编辑器 | 标签关联、焦点顺序、对比度 | 1.3.1 信息结构 / 1.4.3 对比度 ≥4.5:1 |
| 策略配置表单 | 字段标签、错误提示、键盘可达 | 3.3.2 输入目的 / 2.1.1 键盘 |
| 投递看板/状态 | 状态非仅靠颜色（红/绿→加图标/文字） | 1.4.1 颜色用途 |
| 每日日报 | 语义化列表、可缩放文本 | 1.4.4 文本缩放 200% |
| 通知中心 | 可关闭、可键盘操作 | 2.1.1 / 2.4.3 焦点顺序 |

---

## 3. 技术约束（实现侧）

- 前端框架须支持语义化标签 + ARIA；颜色状态必配文字/图标（避免红绿盲误解投递成败）。
- 本机 Agent 确认弹窗为**高危操作确认**，须支持键盘确认/取消且默认可取消（防误投）。
- 字体/缩放不破坏布局（响应式 + 文本缩放 200%）。

---

## 4. 验收（编码期）

- [ ] Web 控制台通过 WCAG 2.1 AA 自动审计（axe/Lighthouse）+ 关键路径屏幕阅读器手测。
- [ ] 投递状态不依赖纯颜色。
- [ ] 本机 Agent 核心控件键盘可达 + 屏幕阅读器可识别。
- [ ] 通知可静音/关闭。

---

> 结论：§19 由「待定」升「已定级」——Web 控制台目标 WCAG 2.1 AA，桌面端参照 AA 交互原则 + OS 辅助功能 API。该定级为设计决策，**不阻塞编码**，编码期按清单落地即可。
