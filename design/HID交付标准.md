## HLD 必须交付的 8 块 + 验收红线

| #    | 块             | 必备产物                                                | 验收红线（做到什么算合格）           |
| :--- | :------------- | :------------------------------------------------------ | :----------------------------------- |
| 1    | 设计目标与约束 | 承接 PRD 目标 + 技术约束（性能/合规/平台封锁/账号安全） | 开发知道"这次设计在什么框框里跳舞"   |
| 2    | 系统架构总览   | 架构图（C4 上下文图 + 容器图）                          | 一眼看清系统由哪几大块组成、各自干嘛 |
| 3    | 模块/组件划分  | 每个模块职责、边界、对外接口、依赖方向（无循环依赖）    | 模块边界无歧义，谁调谁清楚           |
| 4    | 关键流程设计   | 核心链路时序图/流程图（投递流、匹配流、状态机）         | 核心场景 100% 有图，开发照着能写     |
| 5    | 数据架构       | ER 图、存储选型、数据流转                               | 实体关系清楚，选型有理由             |
| 6    | 接口契约       | 模块间/对外 API 定义（协议、入参、出参、错误码）        | 前后端/模块间能并行开发，不互等      |
| 7    | 非功能设计     | 性能/安全/合规/可用性/扩展性**具体方案**（不是口号）    | 每个非功能需求有可落地的技术对策     |
| 8    | 决策与风险     | ADR（为什么选 A 不选 B）+ 技术风险预案                  | 关键决策可追溯，风险有预案           |
