## 1. 审计范围与方法

### 1.1 接口边界枚举（12 个）

| 边界                         | 类型          | 审计前状态                                   |
| -------------------------- | ----------- | --------------------------------------- |
| A 层 REST（客户端↔服务端）          | 同步 HTTP     | 路径表有，字段 schema 缺                        |
| B 层内部服务（Java↔Python/LLM）   | 内网 HTTP/MQ  | B01–B05 仅方法名，无字段                        |
| C 层第三方平台（Boss/猎聘/智联/前程/58） | 浏览器自动化      | 仅采集概述，无契约                               |
| 本机 Agent↔服务端               | WSS 长连接 RPC | **零契约**（最大缺口）                           |
| 事件总线（RabbitMQ）             | 异步 MQ       | 仅"manual ack+DLQ"，无 payload             |
| 统一错误信封                     | 跨层          | 缺 `retryable`/`user_action`，数字/字符串码双向失配 |
| 支付渠道回调                     | 异步 Webhook  | 无签名/幂等契约（资损高危）                          |
| 鉴权模型                       | 跨层          | 分散叙述，无统一基线                              |
| 幂等标准                       | 跨层          | 仅概念，无请求级/业务级双键                          |
| 分页/限流/SLA                  | 跨层          | 缺                                       |
| 异步长任务语义                    | 跨层          | 缺基线                                     |
| 版本化兼容策略                    | 跨层          | 缺                                       |

### 1.2 评估 Rubric（a–g 七维）

a) 类型化 schema  b) 鉴权  c) 幂等  d) 错误契约  e) 版本化  f) 异步语义  g) 限流/SLA

### 1.3 审计前覆盖度结论

- **叙述性覆盖** ≈ 85%（"做了什么"基本都写了）
- **契约级覆盖** ≈ 30%（"字段/方法/错误码/签名怎么定"大量缺失）
- **完整契约** ≈ 25%（可直接照抄编码的契约极少）

**Top 5 缺口（补全前）**：

1. 本机 Agent↔服务端 **零契约**（无 RPC 方法清单 / 设备令牌端点 / 长连接协议）
2. 统一错误信封缺 `retryable`/`user_action` + 数字/字符串码双向失配
3. 22/25 外部 API 与 B01–B05 无字段 schema
4. 事件无类型化 payload（顺序/去重/重放/DLQ 策略空白）
5. 支付回调无签名/幂等契约（资损风险）

## 2. 已落地补全清单（HLD v3.14）

所有补全已落盘并经防漂移校验器复跑（绿灯）。核心链路契约级覆盖率由 ~30% → **核心链路全覆盖**。

### 2.1 §4.7 错误码总表与统一错误信封（业务，权威注册表）

- 统一信封升级：`{ code, message, traceId, retryable, user_action }`
- 码表改为**字符串码为主**、数字码 deprecated 别名，补 `INVALID_JOBS`/`UNAUTHORIZED`/`PLATFORM_DISABLED`/`FORBIDDEN`/`NOT_FOUND` 等缺失码，标注 11 个未用码
- 新增**命名空间桥接**段（LLD `AGENT-1xxx` 映射 + `PAY_*` 码段）

### 2.2 §4.6 事件契约类型化

- 事件信封：`{ eventType, traceId, ts, producer, payload, dedupKey? }`
- 7 个事件逐条补**类型化 payload schema** + 顺序/去重/重放/DLQ 策略表

### 2.3 §4.8 接口契约总规范（跨 A/B/C 层基线）

- 版本化兼容策略、幂等标准（请求级 `idempotencyKey` + 业务级四元组）、鉴权模型（A JWT / B `X-Internal-Token` / Agent OAuth2 / 支付非对称签名）、分页约定、限流/SLA、异步长任务基线（202 + taskId）

### 2.4 §4.9 本机 Agent↔服务端契约（头号缺口，已补）

- 4.9.1 传输与帧：WSS 长连接 + 30s 心跳 + RPC 信封
- 4.9.2 设备令牌生命周期端点：`/device/register`、`/device/token`、`/device/token/revoke`
- 4.9.3 双向 RPC 方法清单：服务端→Agent（ApplyTask.Deliver / Status.Poll / Adapter.HealthCheck / Config.Push / Adapter.LoginGuidance）；Agent→服务端（Result.Report / Status.Observed / Health.Report / Heartbeat / Event.Publish）
- 4.9.4 握手与版本协商端点：`/device/handshake` → 426 Upgrade Required
- 明确：LLD `IpcChannel` 仅本机 IPC，不替代此跨边界契约

### 2.5 §4.10 支付渠道回调契约（资损高危，已补）

- 渠道**非对称签名验签** + `outTradeNo` 幂等 + 对账
- 错误码：`PAY_SIGN_INVALID` / `PAY_DUPLICATE` / `PAY_AMOUNT_MISMATCH`

### 2.6 B01–B05 字段 schema（§4.5）

- B01 `ai/match`、B02 `ai/questions`、B03 `ai/evaluate`、B04 `ai/resume/optimize`、B05 `ai/ats` 补请求/响应字段表
- 同步/异步语义 + 超时熔断 + `traceId` 归因 + `LLM_DEGRADED` 降级路径

### 2.7 文档卫生

- 版本戳统一为 v3.14（原头部 v3.11 / 页脚 v3.10 / 内容 v3.13 不一致，已修正）
