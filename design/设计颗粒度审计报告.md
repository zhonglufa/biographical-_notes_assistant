## 1. 结论（两层含义）

「细粒度规划」应分两层理解：

1. **设计层（design-artifact）颗粒度：已达细粒度 ✅**
   - 20 个模块 LLD + 65（现 66）机器可读 schema / 6 注册表 + 集中式数据库设计（38 DDL / 53 索引）+ 7 份横切设计（威胁模型 / PIPL / 无障碍 / 可观测 / 运维 / 测试 / 风险）。
   - HLD §9.4 全部标 **[闭环]** 或显式 **[部分闭环]**，**无 [待定]/[outlined] 残留**。
2. **代码层（class/function）颗粒度：尚未开始** —— 属编码期产物，非设计文档职责，本轮由 D（编码期脚手架）奠基。

## 3. 真实颗粒度缺口（动态行为为主）

- **缺口① 时序/交互图仅 3 文档**（风险登记表/本机Agent/支付）。异步编排（投递→适配器→通知→支付回调→AI 回写）多为散文。**→ 本轮已闭环**：`时序图规范-关键链路.md` 三张时序（SEQ-1/2/3）。
- **缺口② 事件契约仅 6/25 机器可读**。模块级领域事件未全 schema 化。**→ 本轮已闭环**：`domain-events.event.schema.json`（投递状态/策略变更/支付状态/日报/会员权益）。
- **缺口③ 通知推送投递语义散文级**。**→ 本轮已闭环**：`LLD-通知推送模块-模块设计.md` §8 at-least-once / dedupKey / 幂等 / 重试退避 ≤3 / DLQ。
- **缺口④ DDL 集中不内联**（导航成本，非缺陷）：模块 LLD 需跳 DB LLD 看表。
- **缺口⑤ 数值为默认档**（幻觉阈值 R-10 / 限流 / match_threshold），编码期配置中心定稿——属正常设计留白。
