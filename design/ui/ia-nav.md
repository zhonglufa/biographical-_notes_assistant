# 信息架构与全局导航 · resume-ai-prod 客户端（U0）

> U 阶段基础件之二（与 `00-design-system.html` / `01-app-shell.html` 配套）。
> 作用：定义用户面的信息架构（IA）、导航结构、屏幕清单与 A 层契约的映射，以及全局交互基线。后续 U1–U11 各屏均在此 IA 下展开，保证结构一致、不遗漏任何用户面。

## 1. 产品形态与用户面边界
- **形态**：重客户端（本机 Agent，桌面应用，Electron/WebView 内核）。服务端只做 API/LLM 匹配/通知/状态机，**不在服务端跑浏览器**。
- **用户面范畴**：求职者本人使用的全部界面（B 端运营/管理后台不在本次 U 阶段范围）。
- **本机侧强调**：投递动作由「本机 Agent 在用户浏览器实例中执行」，UI 只负责**收集意图 + 显式确认闸门 + 展示结果**，不直接代发。

## 2. 信息架构（自上而下）
```
简投 · AI 助手（桌面客户端）
├─ 首页 / 待确认投递        ← 核心入口：AI 匹配结果 + 半自动确认闸门
├─ 简历工作台               ← 简历上传/管理/ATS 评分/多版本
├─ 岗位浏览                 ← 搜索/筛选/收藏/忽略
├─ 投递管理                 ← 投递列表/详情/状态机追踪
├─ 策略配置                 ← 匹配阈值/日限额/平台/黑名单
├─ 适配器                   ← 各招聘平台账号连接与启用
├─ 面试模拟                 ← 题库/模拟会话/报告
├─ 通知中心                 ← 站内信/实时推送
├─ 每日日报                 ← 当日投递汇总/推送偏好
├─ 会员                     ← 套餐/下单/权益
└─ 设置                     ← 账号/安全/关于（含登录态）
```

## 4. 导航规则
- **主导航**：左侧固定栏（见 `01-app-shell.html`），11 项常驻；「首页/待确认投递」带未确认数量红点徽标，是最高优先级入口。
- **顶部栏**：全局搜索 + 会员标识 + 通知铃（红点）+ 用户头像（快捷进入设置/登出）。
- **直达**：岗位浏览中「收藏」可一键送入待确认；简历工作台「去匹配」跳转首页；投递管理点击行进入详情。
- **层级深度**：所有功能 ≤ 3 层（导航 → 列表/主页 → 详情），避免深埋。

## 5. 全局交互基线（所有屏遵守）
| 维度 | 规则 |
|------|------|
| 加载 | 骨架屏/行内 spinner；列表加载显示「匹配中…」，不阻塞导航 |
| 空态 | 待确认为空 → 引导「去岗位浏览」；无简历 → 引导「上传简历」；文案正向不责怪 |
| 错误 | 行内提示 + 可重试；账号类错误引导「去适配器重连」，不暴露原始异常 |
| **确认闸门** | 任何「发起投递」必须显式用户点击；批量确认弹二次确认（显示数量/平台）；提供「撤销窗口」（投递后 10s 内可撤销） |
| 限额 | 达日限额时禁用「确认投递」并说明剩余；封号率超阈值时强提示并建议降速 |
| 状态可见 | 账号状态/封号风险在侧栏常驻；投递状态用状态机色（pending=灰 / delivered=绿 / rejected=红 / closed=neutral） |
| 无障碍 | 所有可操作元素可键盘聚焦；状态不仅靠颜色（配文字/图标）；对比度 ≥ WCAG AA |
| 反馈 | 所有写操作有 toast 确认；危险操作（忽略/删除）可撤销或二次确认 |

## 6. 与契约一致性
- UI 展示字段、枚举值（如投递状态、平台名、权益档位）必须与 `design/contracts/` 下对应 schema 一致；原型为 mock，但语义不偏离契约。
- 本文件 + 各 Ux 交互规格是「UI↔契约」对齐的落地索引延伸（见 `design/contracts/implementation-index.md`）。
