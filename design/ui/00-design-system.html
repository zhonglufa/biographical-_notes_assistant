4. 交付约定

每个用户面（U1–U11）交付：① 可交互 HTML 原型（本设计系统组件）置于 design/ui/screens/；② 交互规格（状态/转场/空态/错误/确认闸门）内联或 design/ui/interaction-*.md。原型仅用 mock 数据，不接真实后端与凭据。

5. 动效 / Motion

统一动效规范（token + 现场示例）见 02-motion-system.html，由 U-动效 工作包交付。原则：克制、有目的、可关闭。核心动效：

  • 确认投递（招牌交互）：勾选绘制 → 卡片高亮 → 收起并计数 + Toast，强化"人确认后才发起"的半自动心智。
  • 导航过渡：内容区 200ms 淡入，不大幅位移。
  • 状态脉冲：待确认 / 投递中等需被注意的状态点。
  • 骨架屏：AI 匹配等异步加载占位。
  • 无障碍：尊重系统 prefers-reduced-motion，开启后降级为瞬时切换。

所有时长/缓动 token（--d-fast/base/slow/slower、--e-out/e-std）在 01/02 中保持一致，禁止各屏私自定义动画时长。

6. 响应式规范（Responsive）

客户端目标设备：桌面 PC Web（主） + 移动端 H5（辅助浏览）。所有 U 原型必须在以下三档宽度可正常使用，禁止横向溢出：

  • 桌面 ≥1024px：完整双栏布局（侧栏 232px + 内容）。
  • 平板 768–1023px：内容区收窄，组件自然换行。
  • 手机 ≤768px：侧栏折叠为顶部横向滚动条；卡片/列表行纵向堆叠，操作按钮换行到整行底部、最小点按高度 40px；内容内边距收紧。

断点 token（供 U6–U11 引用）：--bp-sm:640px、--bp-md:768px、--bp-lg:1024px。标准壳折叠 / 卡片堆叠的 CSS 范式见 UI-SELFCHECK.md §5；每个 U 屏在 <style> 末尾引入对应 @media 块。提交前须过 UI-SELFCHECK.md §3 三端自查清单（375/768/1280 渲染、无横溢、无重叠、按钮可点、模态≤90vw、尊重 reduced-motion）。
