# 项目结构与目录规范（前置设计 · 架构师产出）

> **文档性质**：软件工程过程「前置设计」阶段产物，是后续工程师（Java 业务侧）、工程师（Python AI 侧）、QA 的唯一结构权威源。
> **触发原因**：2026-08-18 用户质询「未按软件工程过程、前置设计与项目结构缺失、多角色分工名存实亡、偏离 ADR-001/002 双语言异构」。本文件补齐被遗漏的前置设计。
> **技术栈决策**：严格遵循 HLD ADR-001/002/003/004/010——**双语言异构**：Java(Spring Boot 3.x / Java 17) 业务侧 + Python(FastAPI / 3.x) AI/自动化侧；MySQL 8.0 主从 + Redis 7 + RabbitMQ；Vue3+Element Plus 前端（PC）；本机 Agent 桌面守护进程（浏览器自动化下沉本机）。
> **诚实声明**：截至本文件产出，仓库仅有 `scaffold/`（纯 Python 零依赖草稿，标准库 `http.server`），**Java 业务侧 0 文件、数据层（MySQL/Redis/RabbitMQ）完全未建**。本文件即「现状 → 目标」的纠正蓝图，不掩盖偏离。

## 一、技术栈锁定表（决策均源自 HLD ADR）

| 层 | 技术 | 决策依据 | 现状 | 目标 |
|---|---|---|---|---|
| 业务服务 | Java 17 + Spring Boot 3.x | ADR-002 | **0 文件** | `server-java/` 模块化单体 |
| AI/自动化引擎 | Python 3.x + FastAPI | ADR-002 | 草稿（零依赖 http.server，非 FastAPI） | `server-python/` FastAPI 网关 |
| 关系数据 | MySQL 8.0 主从 | ADR-003 | 无 | 仅 Java 经 JDBC 直连 |
| 缓存/锁/幂等 | Redis 7 | ADR-003 | 无（scaffold 用内存） | Java(Lettuce)+Python(redis-py) 共享 |
| 异步/事件 | RabbitMQ（direct+topic+DLQ） | ADR-004 | 无 | 投递任务/事件总线/延迟队列 |
| PC 前端 | Vue 3 + Element Plus | ADR-010 | 11 个 Vue 屏已建 | `web/` 工程化 |
| 移动端 | uni-app（H5/小程序） | ADR-010 | 未启动 | 上线前范围，本期不建 |
| 本机执行 | 桌面守护进程（Playwright） | ADR-003 | `local_agent.py` 演示（mock 适配器） | `desktop-agent/` 真实浏览器自动化 |
| 契约层 | `design/contracts/` JSON Schema | — | 已就位（A01–A25 + B 层 + 事件） | 三方（Java/Python/前端）统一消费 |

**红线（HLD §2.2/§C.1）**：
- 服务端**不直连招聘平台**、**不部署浏览器沙箱**；浏览器动作一律本机 Agent 执行。
- 服务端**不落用户平台 Cookie**；Cookie 本地加密存本机 Agent。
- Python AI 侧**不直连业务库**，经 REST `/internal/*` + MQ 访问业务数据（ADR-002 存储解耦）。

## 三、服务端 Java 侧模块划分（模块化单体 · 按业务域）

每个模块包路径：`com.resumeai.module.<name>`，标准分层 `controller / service / repository / dto / entity / mapper`。负责的 A 端点与 HLD §3 模块一一对应。

| 模块包 | 业务域 | 负责端点 | HLD 章节 | 核心依赖 | 实现优先级 |
|---|---|---|---|---|---|
| `module.user` | 用户与权限 | A01/A02/A03 + `GET /users/me/permissions` | §3.1 | MySQL(用户表)/Redis(会话/黑名单) | **P0 首批** |
| `module.resume` | 简历工作台 | A04/A05/A06(ats 仅触发) | §3.2 | MySQL(简历表)/OSS | P1 |
| `module.jobs` | 岗位浏览 | A07/A08 | §3.3 | MySQL(岗位表)/AI 匹配(同步≤5s) | P1 |
| `module.application` | 投递状态机(中枢) | A09/A10/A11 | §3.4 | MySQL(投递/事件)/Redis(幂等/锁)/RabbitMQ | **P0 首批** |
| `module.strategy` | 策略配置 | A12/A13 | §3.5 | MySQL(策略表) | P1 |
| `module.adapter` | 平台适配器(服务端编排) | A14/A15 | §3.6 | Redis(锁)/任务通道(本机 Agent) | P1 |
| `module.interview` | 面试模拟(会话/报告/权益) | A16/A17/A18/A19 | LLD-面试模拟域 | MySQL(会话/报告)/AI(/internal/ai/*) | P2 |
| `module.payment` | 支付会员 | A20/A21 | LLD-支付模块 | MySQL(订单)/Redis/支付网关 | P2 |
| `module.notification` | 通知推送 | A22/A23(WS) | LLD-通知推送 | MySQL/RabbitMQ/WS | P2 |
| `module.dailyreport` | 每日日报 | A24/A25 | LLD-每日日报 | MySQL/RabbitMQ | P3 |

**基础设施模块（横切）**：
- `config`：`JwtConfig`(RS256)、`RedisConfig`(Lettuce)、`RabbitConfig`(direct+topic+DLQ)、`MybatisPlusConfig`(@MapperScan 限定 *.repository + 分页拦截器；替代原 JpaConfig)、`OpenApiConfig`(由契约生成)。
- `security`：`JwtAuthFilter`、`PermissionInterceptor`（A03 权益矩阵强制）、`RateLimiter`(token bucket, ADR-010)。
- `event`：`DomainEventPublisher`（封装 RabbitMQ 发布 + `application_event` 审计写）。
- `common`：`ApiResponse<T>`、`BizException`/`GlobalExceptionHandler`、`IdempotencyKey`(Redis SETNX)、`PageResult`。

**模块边界红线**（HLD §3.Boundary）：
- `application` 不执行浏览器操作；`adapter` 不定义业务状态机；`user` 不创建支付订单；`resume` 不润色文本（交 Python）。
- 跨模块调用走应用层方法或领域事件，**禁止跨模块直连表**。

职责（HLD §3.8）：统一承接 LLM 调用（模型路由/降级链/配额/超时），**不落业务数据**（结果经 MQ 由 Java 回写）。

| `routers/ai.py` | B01 match / B05 ats / B02 questions / B03 eval / B04 optimize | `/internal/ai/*`（仅 Java↔Python） | `llm_match.py`(B01) 可复用 |
| `routers/crawler.py` | B10 search-jobs / B11 get-job-detail | 岗位采集聚合入库（Java 只读） | 无，待建 |
| `gateways/llm.py` | — | DeepSeek 路由 + 降级链 + 配额(Redis) | `cost_policy.py`(CostGuard) 可复用 |
| `guard/` | — | 护栏中间件 | `monitor.py`/`monitor_hooks.py`/`crypto_shred.py`/`audit_log.py`/`feature_flags.py` 全部可复用 |

> **可复用判定**：`scaffold/` 的护栏与契约校验逻辑质量达标（双闸门绿、单测绿），应**迁移到 `server-python/guard/` + `server-python/contracts_consumer.py`**，而非重写。现有 `server_app.py`/`server_main.py`（零依赖 http.server）**不纳入 FastAPI 目标**，仅作逻辑参考。

## 七、共享契约层（三方消费 · 版本化）

- **权威源**：`design/contracts/*.schema.json` + `implementation-index.md`（A01–A25 + B 层 + 事件）。
- **Java 消费**：CI 用 `openapi-generator` 由契约生成 DTO/Controller 接口骨架（或手写 DTO 对齐 schema 字段，禁改字段名）。双闸门 `validate_contracts.py` 验证契约不变。
- **Python 消费**：`server-python/contracts_consumer.py` 复用 `contract_runtime.py` 的 schema 加载与校验。
- **前端消费**：`web/src/lib/api.js` 按端点 id 调用，字段与 schema 一致。
- **版本化**：契约 `x-version` 递增，破坏性变更走 `major` 并双闸门拦截。
- **CI 双闸门扩展**（`.github/workflows/ci-cd.yml` 现状仅 Python）：需新增
  - `java` job：maven 编译 + 单元测试 + 契约 DTO 与 `design/contracts` 一致性检查；
  - `py-contract` job：运行 `validate_contracts.py`（闸门1）+ `check_prd_hld_traceability.py`（闸门2）+ Python 测试。

## 十二、架构师 checkpoint 建议（给工程师的起步顺序）

1. **先立工程骨架**：`server-java/pom.xml` + `ResumeAiApplication` + 四大 config，确保 `mvn compile` 通过（CI 验证）。
2. **P0 先建 `user` + `application`**：A01–A03 打通认证链路（JWT+Redis 会话），A09–A11 打通投递中枢（状态机+幂等+RabbitMQ 发任务）——这两条是其他模块的依赖基座。
3. **契约对齐**：每个 Controller 的 DTO 字段必须 == `design/contracts/*.schema.json`；CI 加「Java DTO 字段 vs 契约」一致性校验，防漂移。
4. **双闸门扩展**：`.github/workflows/ci-cd.yml` 加 `java` job，使 `gates` 检查同时覆盖 Java 编译 + 契约校验，恢复「名实相符」。
5. **数据层随 P0 同步**：`user`/`application` 的 MySQL 表 + Flyway migration 与模块同批落地。
