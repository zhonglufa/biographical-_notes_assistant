# B 类验收标准 · 证据看板（76 条）

> **用途**：PRD 审计（见 `design/PRD-验收标准可测试性审计.md` §3）判定 76 条验收标准属 **B 类 = 需人工/观测验证**，无法纯代码断言。"需求命中率"要落地，必须给每条 B 配齐**证据卡**（证据类型 + 采集来源 + 达标结论）。本看板就是那张证据卡总表。
> **状态口径**：`待采集`（尚未产生证据）／`采集中`（已有部分证据待补齐）／`已达标`（证据齐备且评审/演练结论为达成）／`BLOCKED`（缺凭据/法定签署等硬阻塞）。
> **维护**：由自主推进循环（automation-1786905748859）每轮回填证据状态；本文件纳入 git 本地提交，不 push。
> 说明：本看板为**模板与追踪基线**，证据采集需上线后真实演练/巡检/法务签字，非代码可一步达成——故初始状态统一为 `待采集`。

## 采集规范（循环回填时用）

- **证据齐备判定**：该行"建议验证手段"对应的产物（台账/报告/签字/演练记录）存在 + 评审/演练结论为"达成" → 状态改为 `已达标`。
- **BLOCKED 登记**：若证据依赖用户独有动作（真实 DAU、真实部署、法务最终签署、购买 EV 证书等），状态标 `BLOCKED` 并注明依赖项，等对应阶段（S2/S3/上线）解锁。
- **回填节奏**：自主循环每推进一个相关章节即更新对应行状态；季度 Game day / 上线后集中回填生产类证据（B13/B43 等）。
- **看板与命中率联动**：B 类 76 条全部 `已达标` 时，"需求命中率"分母中 B 部分 76/76 计入通过，配合 A/C 即逼近 226/226。
