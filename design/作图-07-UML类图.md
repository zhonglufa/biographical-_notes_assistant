## 3.6.1 决策目标

| 问题 | 答案 |
|------|------|
| 支持什么决策 | 核心领域模型的结构？服务接口定义？DTO 结构？类间关系？ |
| 谁读 | 后端开发、前端开发、架构师、Code Reviewer |
| 决策后果 | 类结构错了 → 代码实现混乱；接口契约错 → 上下游联调返工；继承层次错 → 难以扩展 |
| 何时用 | 领域建模、模块边界划分、API 契约定义、Code Review、设计评审 |
| 何时不用 | 仅需描述单次交互（用时序图）、状态流转（用状态机）、流程编排（用活动图） |

## 3.6.2 UML 2.5 语法合规

### 类元素

| 元素 | UML 2.5 规范 | SVG 实现 | 常见错误 |
|------|-------------|----------|----------|
| **类名** | 顶部一栏，加粗，名词单数 | `<text>` font-weight: bold | 普通字重、未加粗 |
| **属性** | 可见性 + 名称 + 类型（可选初值） | `+ name: String` | 漏可见性符号 |
| **方法** | 可见性 + 名称 + 参数 + 返回类型 | `+ method(args): ReturnType` | 漏返回类型 |
| **抽象类** | 类名斜体，方法可标 `{abstract}` | `font-style: italic` | 普通字重 |
| **接口** | `<<interface>>` 构造型，可使用 lollipop 球状符号 | `<<interface>>` 在类名上方 | 漏构造型标记 |
| **枚举** | `<<enum>>` 构造型，字面量列表 | `<<enum>>` | 用普通类代替 |
| **静态成员** | 下划线标识 | `<text>` text-decoration: underline | 无标识 |
| **包** | `<<package>>` 容器，可嵌套 | 带包名标签的圆角矩形 | 散乱无分组 |

### 关系元素（6 种关系类型）

| 关系 | UML 2.5 规范 | SVG 实现 | 常见错误 |
|------|-------------|----------|----------|
| **泛化（继承）** | 实线 + 空心三角箭头，箭头指向父类 | `stroke="实线"` + 空心三角 marker | 用普通实线箭头 |
| **实现** | 虚线 + 空心三角箭头，箭头指向接口 | `stroke-dasharray="6,4"` + 空心三角 | 用实线 |
| **关联** | 实线 + 普通箭头（可单向/双向） | 实线 + 普通箭头 marker | 用三角箭头 |
| **依赖** | 虚线 + 普通箭头，指向被依赖方 | `stroke-dasharray="6,4"` + 普通箭头 | 用实线 |
| **聚合** | 实线 + 空心菱形，菱形在整体侧 | 实线 + 空心菱形 marker | 用实心菱形 |
| **组合** | 实线 + 实心菱形，菱形在整体侧 | 实线 + 实心菱形 marker | 用空心菱形 |
| **多重性** | 关联端标注 `1`、`*`、`0..1`、`1..*` | `<text>` 在关联端 | 漏多重性 |
| **角色名** | 关联端标注角色名 | `<text>` 在关联端 | 漏角色 |
| **自关联** | 类指向自身的环回箭头 | 折线 + 箭头 | 用直接箭头 |

### 可见性符号

| 符号 | 含义 | UML 2.5 |
|------|------|---------|
| `+` | public | 公开 |
| `-` | private | 私有 |
| `#` | protected | 受保护 |
| `~` | package | 包内可见 |

## 3.6.3 元素完备性

| 元素 | 必须 | 说明 |
|------|------|------|
| 所有类 | ✅ | 名称 + 属性 + 方法三栏 |
| 关系 | ✅ | 6 种关系类型正确使用 |
| 可见性 | ✅ | `+` / `-` / `#` / `~` 必须标注 |
| 多重性 | ✅ | 关联端必须标注（`1`、`*`、`0..1`、`1..*`） |
| 接口/抽象类 | ✅ | 构造型标记（`<<interface>>`）+ 斜体 |
| 角色名 | ✅ | 关联端非自明时必须标注 |
| 枚举 | ✅ | 用 `<<enum>>` 标记 |
| 包 | 可选 | 逻辑分组用 `<<package>>` 容器 |
| 图例 | ✅ | 关系符号含义说明 |
| 静态成员 | 可选 | 下划线标识 |

## 3.6.4 布局规范

- **三栏布局**：顶部 = 类名 / 中部 = 属性 / 底部 = 方法，分隔线清晰
- **类尺寸**：最小 120×80px，字段行高 16px，类名栏高度 24px
- **关联方向**：箭头指向被引用类（依赖方向）
- **继承层次**：父类在上，子类在下（泛化箭头向上）
- **接口实现**：用 `<<interface>>` 球状符号（lollipop）或虚线三角箭头
- **禁止**：类之间连线穿过其他类（零容忍），必须用折线绕行
- **对齐**：同类层级垂直对齐，关联类水平排列
- **包容器**：相关类放入 `<<package>>` 容器，容器不重叠
- **留白**：类与类之间最小间距 40px，避免视觉拥挤

## 3.6.6 审查清单

```
□ 6.1  决策目标：类图覆盖了哪些领域模型？目标读者能据此实现代码？
□ 6.2  UML 语法：可见性 (+/-/#/~) 是否完整？关系符号是否正确？
□ 6.3  元素完备性：是否覆盖了核心领域模型？类名/属性/方法齐全？
□ 6.4  关系正确：泛化/实现/关联/依赖/聚合/组合使用正确？箭头方向无误？
□ 6.5  跨图一致：类名与代码一致？与 ER 图实体对应？与时序图消息一致？
□ 6.6  图例：是否包含关系符号含义？
□ 6.7  生命周期状态：状态相关类是否标注状态字段？
□ 6.8  布局：连线是否穿越其他类？继承层次是否清晰？
□ 6.9  接口与抽象类：<<interface>> 标记、斜体是否正确？
□ 6.10 多重性：关联端是否标注 1 / * / 0..1 / 1..*？
```

## 3.6.7 反模式

| 反模式 | 错误表现 | 正确做法 |
|--------|----------|----------|
| 属性过多 | 一个类 20+ 属性 | 拆分为多个子类或聚合根 |
| 无关系线 | 类之间没有关系线 | 必须标注类间关系 |
| 可见性缺失 | 属性/方法没有 +/- 标记 | 必须标注可见性 |
| 类名不规范 | 类名不是大驼峰 | 大驼峰命名（PascalCase） |
| 缺少可见性 | 属性无 `+ - # ~` 符号 | 必须标注 |
| 关系类型错用 | 继承用关联箭头表示 | 泛化 = 实线三角，实现 = 虚线三角 |
| 单向关联未标角色 | 缺角色名 | 关联端必须有角色名（当语义不明时） |
| 多重性漏标 | `List<>` 集合无 `*` | 集合 = `*`，可选 = `0..1` |
| 接口无标记 | 普通类实现接口无 `<<interface>>` | 必须用 `<<interface>>` 构造型 |
| 抽象类未斜体 | 抽象类名普通字重 | 抽象类名斜体 |
| 组合/聚合混淆 | 强生命周期用聚合 | 同生命周期强拥有 = 组合 |
| 双向关联滥用 | 全部双向关联 | 仅在确实双向导航时使用 |
| 跨类连线 | 连线穿过其他类 | 折线绕行或调整布局 |

### 关系说明

| 源类 | 目标类 | 关系类型 | 多重性 | 说明 |
|------|--------|----------|--------|------|
| User | ResumeSet | 组合 ◆ | 1 → 1 | User 拥有简历集合，生命周期一致 |
| ResumeSet | Resume | 聚合 ◇ | 1 → * | 简历集合包含多个简历 |
| ApplicationRecord | Job | 关联 | * → 1 | 投递记录引用一个职位 |
| ApplicationRecord | Resume | 关联 | * → 1 | 投递记录引用一份简历 |
| Job | ApplyStatus | 依赖 | - | 职位使用枚举状态 |
| ApplyService | IApplyChannel | 依赖 | - | 服务依赖渠道接口 |
| BossApplyChannel | IApplyChannel | 实现 | - | 实现投递渠道接口 |
| LagouApplyChannel | IApplyChannel | 实现 | - | 实现投递渠道接口 |
| ApplyService | ApplyQueue | 依赖 | - | 服务使用任务队列 |
| ApplicationRecord | ApplyStatus | 关联 | - | 投递记录关联状态 |

### 关键设计点

1. **抽象渠道**：`IApplyChannel` 接口 + 多个实现类（开闭原则，便于新增 BOSS/Lagou/拉勾等渠道）
2. **聚合边界**：`User → ResumeSet → Resume` 形成清晰的聚合根（User 是聚合根，ResumeSet 是值对象集合）
3. **状态枚举**：`ApplyStatus` 统一管理投递生命周期状态（PENDING/SUBMITTED/FAILED/SUCCESS/REJECTED）
4. **依赖倒置**：`ApplyService` 依赖 `IApplyChannel` 接口而非具体实现，便于 Mock 测试
5. **异步队列**：`ApplyQueue` 抽象任务调度，服务层不直接耦合具体 MQ 实现
