## 1. PIPL §24 自动化决策（AI 匹配 + 半自动投递）

### 1.1 适用性判定（产品形态锚定）

产品为 **「半自动投递」**：AI 仅做岗位匹配评分与建议（`job_match` 异步管道，`matchScore 0–100` + `band green/blue/gray` + `matchReason`），**每一次实际投递由用户显式确认/发起**（非全自动无人值守）。

- 因此**不属于**「对个人权益有重大影响的全自动化决策」典型情形；
- 但为稳妥与用户信任，按「从严」设计提供三类保障（见 1.2–1.3），避免合规灰色地带。

### 1.2 告知与同意

- **首次启动告知页**：说明 AI 参与匹配的范围、数据用途、隐私政策链接（PRD §隐私）。
- **AI 匹配总开关**：默认开启，可一键关闭；关闭后用户仅见「原始列表 + 规则筛选」，不影响手动浏览/投递核心功能。
- **敏感自动化动作可关**：自动续费提醒、定时投递等默认关闭或需二次确认，提供人工复核通道。

### 1.3 可解释性与拒绝权

- 匹配已具备可解释性：`matchReason` 字段 + `band` 分级，用户可查看「为何推荐」。
- **拒绝 AI 推荐通道**：用户可选择「不看 AI 推荐，仅看原始列表」（等价于拒绝自动化决策）。
- 关闭 AI 匹配后，系统不基于用户画像做主动推送，仅响应用户显式查询。

### 1.4 影响评估（DPIA 雏形）

| 项 | 内容 |
|----|------|
| 处理目的 | 辅助求职者匹配岗位、半自动投递、面试模拟 |
| 数据类型 | 简历/求职意向/账号偏好/本机平台 Cookie（本地持有）/投递与 HR 互动记录 |
| 第三方关系 | 平台凭证仅本地信封持有、不上传（本产品非平台数据控制者，系代用户操作）；LLM 网关仅传必要文本 |
| 风险 | 画像泄露、误匹配导致投递偏差、Cookie 泄露 |
| 缓解 | 信封加密 + 差分隐私 k=50 + 最小采集 + 拒绝开关 + 审计日志 |

### 1.5 待律师确认点（显式登记，非静默）

- 当前「半自动 + 用户确认」是否完全排除 §24 强制情形，还是需补强告知。
- 告知页文案与隐私政策的合规措辞。
- 拒绝权实现方式（开关 vs 独立通道）是否满足监管预期。

## 2. DSAR 全流程（查阅 / 更正 / 删除 / 可携）

### 2.1 数据地图（删除链路前置）

| 数据位置 | 内容 | 持有方 | 删除方式 |
|----------|------|--------|----------|
| 服务端 MySQL | user / resume / resume_version / job_favorite / job_view / job_match / strategy_config / user_preference / ats_report / member_order | 服务端 | 软删 `deleted_at` → 异步 purge 作业 |
| 本机 SQLite | 去重键 / 任务状态 / 在途进度 | 用户设备 | 本地直接 purge（用户设备） |
| 结构化日志 | ts/level/service/trace_id/`user_id`(哈希)/event | 服务端 | `user_id` 哈希化，删除时不可反查；审计日志去标识保留 |
| 加密备份 | 同 MySQL 快照 | 服务端 | 按保留期；信封加密凭证以**密钥销毁(crypto-shred)**失效 |
| 平台 Cookie | 仅本地信封，不上传 | 用户设备 | 清本地信封即失效（不下发至服务端） |

### 2.2 四权实现

- **查阅**：用户控制台「我的数据」页，列出全部持有字段与来源；`user_preference`/`strategy_config` 可直读。
- **更正**：简历/意向/偏好支持编辑（已有 简历工作台 LLD 字段级 diff）；更正经版本快照（ADR-012）留痕。
- **删除（被遗忘权）**：触发 `DELETE /api/dsar/delete` → 标记 `deleted_at` → 异步 purge MySQL + 下发本机 Agent 清本地 SQLite + 日志去标识 + 备份 crypto-shred（销毁该用户 KEK 派生密钥）。
- **可携**：导出为 JSON/PDF（简历 + 偏好 + 投递记录），**不含平台凭证**。

### 2.3 删除链路（端到端，关键）

```
用户请求删除
  → 服务端 MySQL: UPDATE ... SET deleted_at=now()（软删，立即可逆窗口 7d）
  → 异步 purge 作业: 物理删除各表用户行（跳过 member_order 财务留存行，见 2.4）
  → 本机 Agent: 收到 dsar.purge 事件 → 清本地 SQLite 用户行 + 清本地 Cookie 信封
  → 日志: user_id 已哈希，删除后无法关联；审计日志保留但去标识
  → 备份: 该用户信封 KEK 销毁 → 历史备份中凭证不可解密（crypto-shred）
```

### 2.4 留存与法定例外

- 财务类（`member_order`）：按税法/支付合规留存，删除请求对其仅做去标识，不屈从于被遗忘权（法定例外）。
- 其余用户数据：账号注销后 ≤30 天物理删除（法定期限内）。
- 差分隐私 k=50 已在隐私 LLD 落实，聚合报表不关联个人。

### 2.5 DSAR SLA（提议值，待律师定稿）

| 权利 | 提议 SLA |
|------|----------|
| 查阅 | ≤72h |
| 更正 | 即时（用户自助） |
| 删除 | ≤30 天（法定期限内） |
| 可携 | ≤72h |
