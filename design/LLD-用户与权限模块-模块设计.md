## 0. 模块定位与边界

- **职责**（HLD §3.1）：管理账号生命周期、登录态与角色权益判定。
- **边界**：不负责支付订单创建（只收 C5 事件）；不改写平台 Cookie（仅存取密文，I2 约束）；权限判定在服务端每次接口调用强制执行，前端仅做展示隐藏（防越权）。
- **依赖**：MySQL（用户表 / 平台账号元信息）、Redis（会话 / 黑名单）、支付模块（会员事件 C5）。

## 1. 账号生命周期与认证

- 登录方式：邮箱 / 手机验证码 / 微信扫码；JWT **RS256 无状态令牌**（ADR-017/018）。
- 令牌：access≤15min、refresh≤7d；刷新走 `POST /auth/refresh`（A02）；校验强制权限判定。
- 第三方授权：微信授权码换取会话；黑名单（Redis）用于封禁 / 风险账号拦截。

## 2. 权限矩阵与权益判定（§6.11 B4）

订阅权益矩阵（功能 × 套餐，驱动权限系统设计的总制品）：

| 功能 | 免费版 | 专业版 | 高级版 | 管理员 |
|------|------|------|------|------|
| 接入平台数 | ≤3 | 全部 | 全部 | 全部 |
| 日投递上限 | 30 | 100 | 100 | 100 |
| 移动端 | 仅查看 | 完整 | 完整 | 完整 |
| AI 面试模拟 | — | ✓ | 无限 | ✓ |
| 语音练习 | 文本仅查看 | ✓ | ✓ | ✓ |
| 多简历版本 | — | — | ✓（§25.2） | ✓ |
| 优先适配器支持 | — | — | ✓（SLA 量化） | ✓ |

- **判定纪律**：A03 字段级权限校验强制执行；权限码表见 **§2.1（T-UP-1 设计态闭环）**；任何特权接口须持对应 role（Bearer+role，如 A09/A13/A15）。

## 2.1 角色枚举与权限码表（T-UP-1 设计态闭环）

> 闭合 §7 待决 T-UP-1：编码期仅做最终命名，设计态角色全集 + 权限码全集 + 判定规则已在此定义（类比其它「默认档」设计留白，不阻塞设计闭环）。

**角色枚举 `role`**（JWT claims `role` 取值）：

| role | 含义 | 权益来源 |
|------|------|----------|
| `free` | 免费版 | 权益矩阵免费档（fail-closed 默认） |
| `pro` | 专业版 | 权益矩阵专业档 |
| `premium` | 高级版 | 权益矩阵高级档（含优先支持指标） |
| `admin` | 管理员 | 全功能 + 后台运营 |

**权限码 `perm`**（A03 字段级判定，Bearer 须含对应 role 方可调用特权接口）：

| perm code | 说明 | 要求 role |
|-----------|------|-----------|
| `resume:read` `resume:write` | 简历读写 | 任意登录用户 |
| `resume:version:multi` | 多简历版本 | `pro`/`premium`/`admin` |
| `apply:execute` | 发起投递 | 任意登录用户（受日上限约束） |
| `apply:platform:unlimited` | 接入全部平台 | `pro`/`premium`/`admin`（免费 ≤3） |
| `interview:sim:unlimited` | 无限 AI 面试模拟 | `premium`/`admin`（`pro` 限次） |
| `voice:practice` | 语音练习 | `pro`/`premium`/`admin` |
| `adapter:prioritized` | 优先适配器支持 | `premium`/`admin` |
| `admin:ops` | 后台运营操作 | `admin` |
| `admin:config` | 配置中心写 | `admin` |

**判定规则**：
1. 每次接口调用由网关/服务端强制 A03：`required_role(perm) ⊆ user.role` 否则 `403 FORBIDDEN`（错误码 `FORBIDDEN`，见 `error-codes.json`）。
2. 权益来源不确定（C5 未达 / 解析失败）→ **fail-closed 按 `free` 处理**，不放大权限（§3）。
3. 字段级隐藏：前端仅做展示隐藏，服务端为唯一权威（防越权）。

## 3. 会员权益实时生效（C5）

- 订阅支付模块 `member.plan.changed` 事件（C5）：`{ userId, plan, effectiveAt, orderNo }`，按 `orderNo` 去重，强一致，失败阻塞重试（HLD §876）。
- 收到后权益矩阵实时生效（下一次调用即时生效），不主动查询支付订单（HLD §400）。
- 权限判定 fail-closed：权益来源不确定时按免费版处理，不放大权限。

## 4. 会员降级与存量保留

- 过期自动降级免费版（§20.2 Subscription 状态机 expired→downgraded）；存量配置保留不可改，进行中任务允许执行完毕（HLD §410）。
- 高级版"优先支持"映射为 3 个可操作指标——工单响应 48h（免费/专业 7d）、适配器 beta 抢先、新平台接入优先队列（HLD §411）。

## 5. 会话与黑名单

- Redis 持有 access/refresh 状态、设备绑定、封禁名单；登出 / 改密触发 refresh 失效（短黑名单）。
- 风控：异常高频触发二次验证 + 限流（PRD §18.2）；具体阈值待决 T-UP-3。

## 6. 数据对齐

- `user`（id，uk email/phone）、`platform_account`（仅存元信息，Cookie 密文留本机，§C.5）。
- JWT 设计：RS256 非对称，公钥可轮换；claims 含 `sub/role/plan/exp`，不含敏感字段。
