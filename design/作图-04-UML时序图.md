## §3.3 UML 时序图

#### 3.3.1 决策目标

| 问题 | 答案 |
|------|------|
| 支持什么决策 | 关键流程的交互时序？同步/异步？异常如何处理？超时/重试策略？ |
| 谁读 | 后端开发、测试 |
| 决策后果 | 时序错了 → 实现逻辑错误；异常路径没画 → 线上故障 |

#### 3.3.2 UML 2.5 语法合规

| 要素 | UML 2.5 规范 | SVG 实现 | 常见错误 |
|------|-------------|----------|----------|
| **同步消息** | 实线 + 实心三角箭头 `──▶` | `stroke="black"` + `marker-end="url(#arrowSync)"` | 用开放箭头 |
| **异步消息** | 实线 + 开放箭头 `──▷` | `stroke="black"` + `marker-end="url(#arrowAsync)"` | 用实心箭头 |
| **返回消息** | 虚线 + 开放箭头 `- - ▷` | `stroke-dasharray="6,4"` + `marker-end="url(#arrowReturn)"` | 用实线 |
| **自调用** | 消息线回到自身 lifeline | 环状路径：右→下→左→上 | 直接横线指向自己 |
| **激活条** | 矩形条，长度 = 执行时间 | `<rect>` 宽度 = 4px，y 坐标对应开始/结束 | 整条 lifeline 画满 |
| **嵌套激活** | 激活条内嵌套更小的激活条 | 外层宽 4px，内层宽 6px 偏移 2px | 平铺排列 |
| **alt 片段** | 虚线分隔多个操作数，有监护条件 | `<path>` 虚线 + `<text>` 监护条件 | 用注释代替 |
| **opt 片段** | 可选路径，一个操作数 | 同 alt 但只有一个分区 | 用 alt 代替 |
| **loop 片段** | 循环边界，标注 min/max | `<path>` + `<text>` 如 `loop [1..3]` | 不标注循环次数 |
| **break 片段** | 异常中断，覆盖剩余交互 | `<path>` + `<text>` 如 `break [错误]` | 用注释代替 |
| **生命线** | 虚线 + 头部 `实例名:类名` | `stroke-dasharray="8,4"` + `<rect>`+`<text>` | 只写类名不写实例名 |
| **时间约束** | 标注在消息旁 | `<text>` 如 `{≤200ms}` | 不标注时间约束 |

#### 3.3.3 元素完备性

| 元素 | 必须 | 说明 |
|------|------|------|
| Lifeline | ✅ | 所有参与交互的角色/系统/组件，命名 `实例名:类名` |
| 同步消息 | ✅ | 至少覆盖所有请求调用 |
| 异步消息 | ✅ | 异步场景必须有 |
| 返回消息 | ✅ | 每个同步消息必须有对应的返回 |
| 激活条 | ✅ | 同步调用的执行时间必须用激活条表示 |
| alt 片段 | ✅ | 有分支逻辑时必须用 alt |
| opt 片段 | ✅ | 有可选路径时必须用 opt |
| loop 片段 | ✅ | 有循环时必须用 loop，标注循环次数 |
| break 片段 | ✅ | 有异常中断时必须用 break |
| 时间约束 | ✅ | 性能关键路径标注时间约束 |
| 图例 | ✅ | 线型/箭头/片段类型含义 |

#### 3.3.4 线条与间距

| 参数 | 标准值 | 说明 |
|------|--------|------|
| Lifeline 间距 | 80px（最小） | 两条 lifeline 之间的水平距离 |
| 消息线间距 | 24px（最小） | 两条平行消息线之间的垂直距离 |
| 激活条宽度 | 4px | 标准激活条 |
| 嵌套激活条宽度 | 6px（外层），4px（内层），偏移 2px | 嵌套时外层比内层宽 |
| 激活条与 lifeline 间距 | 0px（紧贴） | 激活条左边缘与 lifeline 重合 |
| 片段框与 lifeline 间距 | 左右各 8px | 片段框不紧贴 lifeline |
| 标签与消息线间距 | 4px | 文字在线上方或左侧 |
| 生命线虚线长度 | 实段 8px + 空段 4px | 统一 |

#### 3.3.6 审查清单

```
□ 3.1  决策目标：这张时序图覆盖了哪个关键场景？
□ 3.2  UML 语法：同步/异步/返回消息线型是否正确？
□ 3.3  激活条：所有同步调用是否有激活条？长度是否正确？
□ 3.4  组合片段：alt/opt/loop/break 是否覆盖了所有分支？
□ 3.5  监护条件：每个片段是否有明确的监护条件？
□ 3.6  返回消息：每个同步消息是否有对应的返回消息？
□ 3.7  时间约束：性能关键路径是否标注了时间约束？
□ 3.8  异常路径：是否覆盖了超时、失败、重试路径？
□ 3.9  线条规范：lifeline 间距 ≥ 80px？消息线间距 ≥ 24px？
□ 3.10 复杂度：lifeline ≤ 8？消息 ≤ 30？
□ 3.11 元数据：是否完整？
□ 3.12 可追溯：流程/策略/异常是否对应 PRD 或 ADR？
□ 3.13 跨图一致：lifeline 名称/API 调用/数据实体是否一致？
□ 3.14 图例：是否包含线型/箭头/片段类型的含义？
□ 3.15 生命周期状态：是否正确？
□ 3.16 渲染顺序：组合片段背景是否在激活条之前绘制？
□ 3.17 图例格式：是否包含背景框 + 标题 + 五项说明（同步/异步/返回/alt/激活条）？
```

#### 3.3.7 反模式

| 反模式 | 错误表现 | 正确做法 |
|--------|----------|----------|
| 幸福路径 | 只画正常流程，没有异常/超时/失败分支 | 至少画一个异常分支 |
| 无激活条 | 整条消息序列没有激活条，看不出同步/异步 | 每个同步调用必须画激活条 |
| 激活条满格 | 整条 lifeline 画满激活条 | 只有执行时间才画激活条 |
| 返回消息缺失 | 有请求没有返回 | 每个同步消息必须有返回 |
| 分支当注释 | 用文字注释代替 alt 片段 | 必须用 UML 组合片段 |
| 无限循环 | loop 片段没有标注循环次数 | 标注 `[1..3]` 或 `[直到成功]` |
| 线型混乱 | 同步用开放箭头，异步用实心箭头 | 严格遵循 UML 2.5 规范 |
| 消息过多 | 一张图塞了 30+ 条消息 | 按阶段拆分为多张图 |
| alt 遮挡激活条 | alt 背景在激活条之后绘制，激活条被遮挡 | alt 背景必须在激活条之前绘制 |
| 图例格式不完整 | 图例缺少背景框、缺少 alt 或激活条说明 | 图例必须包含背景框 + 五项说明 |

#### 3.3.8 渲染顺序与图例规范

##### 3.3.8.1 渲染顺序（Z 轴顺序）

SVG 中元素的渲染顺序由文档顺序决定：先绘制的元素在后绘制的元素之下（即后绘制的元素在上层）。时序图中各元素的绘制顺序必须遵循以下规则：

| 顺序（先→后） | 元素 | 说明 |
|--------------|------|------|
| 1（最底层） | 组合片段背景（alt/opt/loop/break） | 透明（`fill="none"`），最先绘制，确保不遮挡任何后续元素 |
| 2 | 激活条（`#DBEAFE`） | 在组合片段背景之上，但 **必须在** namebox 之前绘制 |
| 3 | 组合片段圆角矩形标签（namebox） | 浅灰填充（`#F5F5F5`），利用自身背景覆盖下方激活条，确保文字不被遮挡 |
| 4 | 生命线（虚线） | 在 namebox 之上 |
| 5 | 消息线（箭头线） | 在生命线之上 |
| 6 | 消息标签 / 监护条件 | 在最上层，确保可读性 |
| 7 | 图例背景 | 图底部独立区域，不遮挡主图元素 |

**关键规则**：
1. 组合片段背景 `<rect>` 必须使用 `fill="none"`（透明背景），彻底避免遮挡下层元素。
2. 组合片段边框使用 `stroke="#AAAAAA" stroke-width="0.5"`（极细实线边框），视觉轻量精致，与普通消息线区分。
3. 组合片段圆角矩形标签（namebox）使用 `<rect rx="4" fill="#F5F5F5" stroke="#AAAAAA" stroke-width="0.5"/>`，确保片段类型可识别。
4. 组合片段内部操作数分隔线使用 `stroke="#D0D0D0" stroke-width="0.5" stroke-dasharray="3,3"`（极细淡灰虚线），与片段边框区分。
5. **激活条** 必须在 **namebox 之前** 定义。由于激活条纵贯整个生命线活跃期（y=148~678），会与 namebox 区域（y=388~410）重叠。将激活条置于 namebox 之前，利用 namebox 的 `#F5F5F5` 填充背景覆盖重叠区域的激活条，确保 namebox 文字不被遮挡。
6. namebox 文字 `y` 坐标必须在矩形范围内（矩形高 22px，文字 baseline 约在矩形垂直中心偏下 2~3px）。

**正例（推荐样式）**：
```
✅ <!-- alt 片段：透明背景 + 极细实线边框 + 圆角矩形 namebox -->
<rect x="96" y="398" width="920" height="204" fill="none" stroke="#AAAAAA" stroke-width="0.5"/>

<!-- 激活条在 namebox 之前绘制，namebox 背景覆盖重叠区域 -->
<rect x="148" y="148" width="4" height="320" fill="#DBEAFE"/>

<!-- namebox 利用 #F5F5F5 背景覆盖下方激活条，确保文字不被遮挡 -->
<rect x="96" y="398" width="52" height="22" rx="4" fill="#F5F5F5" stroke="#AAAAAA" stroke-width="0.5"/>
<text x="122" y="401" text-anchor="middle" font-size="11" font-weight="bold" fill="#333333">alt</text>

<line x1="104" y1="506" x2="1008" y2="506" stroke="#D0D0D0" stroke-width="0.5" stroke-dasharray="3,3"/>  <!-- 分隔线 -->
→ 激活条在 namebox 之下，namebox 文字不被遮挡；文字 y=401 在矩形（y=398~420）范围内居中
```

**反例（禁止样式）**：
```
❌ <!-- 实色填充背景 + 无 namebox -->
<rect x="96" y="398" width="920" height="204" fill="#F0F0F0" stroke="#666666" stroke-width="1"/>
<text x="110" y="418" font-size="11" fill="#333333">alt</text>
→ 实色填充可能遮挡激活条，无 namebox 不符合 UML 规范，实色边框视觉过重

❌ <!-- 实色背景 + 实色边框 -->
<rect x="96" y="398" width="920" height="204" fill="#F0F0F0" stroke="#666666" stroke-width="1"/>
→ 实色填充遮挡激活条，实色边框不够美观
```

##### 3.3.8.2 图例规范

所有时序图底部必须包含统一格式的图例，格式如下：

| 元素 | 规范 |
|------|------|
| 背景框 | `fill="#F9FAFB" stroke="#D1D5DB" rx="6"` |
| 标题 | "图例"，11px Bold，`#333333` |
| 同步消息 | 实线实心三角箭头 + "同步调用" |
| 异步消息 | 实线空心三角箭头 + "异步消息" |
| 返回消息 | 虚线空心三角箭头 + "返回/异常" |
| alt 条件分支 | 灰色极细实线圆角矩形框示意 + "alt 条件分支" |
| 激活条 | 浅蓝矩形（`#DBEAFE`，4px 宽）+ "激活条（执行时间）" |
| 位置 | 图底部，y > 主图最低元素 y + 20px |
| 间距 | 图例矩形与上方最后一条消息/箭头之间至少保留 20px 空白间距 |
| 行间距 | 各项之间 ≥ 6px |

**图例示例布局**：
```
┌──────────────────────────────────────────────────────────┐
│ 图例                                                      │
│ ─▶ 同步调用    ─▷ 异步消息    - - ▷ 返回/异常              │
│ [alt] alt 条件分支    [█] 激活条（执行时间）                 │
└──────────────────────────────────────────────────────────┘
```

**检查方式**：图例 y 起始坐标 > 所有主图元素 y 结束坐标 + 20px，确保图例不遮挡主图元素。
