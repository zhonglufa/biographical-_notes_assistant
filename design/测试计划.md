# 系统测试计划（v1.0）

> 关联文档：PRD v4.5 §11 验收标准；HLD v3.30（§23 韧性 S1–S13 / §28 生产事故预防 N4/N6/N7 / §10 交付物）；`design/contracts/`（机器可读契约 + 零依赖校验器）；各模块 LLD v1.0。
> 范围：覆盖「本机 Agent（客户端执行）+ 服务端 Java（业务/AI 编排）+ 平台适配器 + 面试模拟域 + 支付 + 通知 + 投递 + 数据库」全链路的测试策略与发布门禁。
> 本文为 P2 测试计划文档（审查报告 P2 收口项 #169），与 `部署运维手册`（#171）、风险登记表复评（#170）共同构成 P2 文档交付。

## 0. 测试目标与原则

- **目标**：在「半自动投递 + 用户显式确认」产品形态下，证明——
  1. 核心链路（采集 → 匹配 → 确认投递 → 状态回写 → 通知 → 日报；面试模拟全流程）正确、幂等、可观测、fail-closed；
  2. 接口契约不漂移（机器可校验）；
  3. 资损 / 平台封禁 / 并发三类高危风险有可验证防护。
- **原则**：
  - **契约优先**：任何接口变更先过 `design/contracts/validate_contracts.py`（正向样本通过 + 反向样本证伪 + 注册表自洽 + 错误码唯一），pre-commit + CI 双闸门强制拦截。
  - **Mock 优先于真实平台**：适配器测试一律用 Mock 适配器，不触真实 Boss/猎聘/智联等，避免触发平台反自动化封禁（R-类风险 fail-closed，非静默忽略）。
  - **不臆造**：解析 / ATS / 匹配相关断言以 PRD 定义与 LLD 门禁为准；`accuracy≥98%` 等实测值标 `[Hypothesis]`，不假装已达标。
  - **显式登记缺口**：PIPL 自动化决策(§24) / DSAR 全流程 / 威胁模型（法务三块，延后）与无障碍（§19 待定）不在本计划覆盖，登记为「待测待决」而非「已测」（见 §8）。

## 2. 契约测试（门禁级，最高优先级）

- 复用 `design/contracts/validate_contracts.py`：当前 **65 schema / 6 注册表全绿**。新增端点契约必须先补 schema + samples 证伪再合入。
- **A 层 25 端点（A01–A25，全 fully-detailed）** 逐一有请求/响应 schema + 证伪样本；B 层 b01–b05、面试模拟域 6 方法、本机 Agent RPC、C 层 `device/*` 与 `payments/callback` 同理。
- `api-contracts/openapi.json`（OpenAPI 3.1.0）经 Prism Mock 提供消费者契约；**Pact 消费方测试留编码期嵌入**（登记为 `[LLD 细化]`，不阻塞当前收口）。
- 回归：`check_prd_hld_traceability.py`（MUST_TRACE 全覆盖 + 版本 4.5 一致）随 pre-commit 运行，拦截章节/版本漂移。

## 3. 关键风险域专项

### 3.1 支付资损（R-04，最高）
- 订单五态机（`pending→paid→activated→expired→refunded + closed`）状态转移矩阵全覆盖（LLD-支付模块 §订单状态机）。
- A21 回调：渠道签名验签失败 / 金额比对不一致 / 重复回调（幂等键）三种必测；15min 双源对账掉单兜底。
- 退款：原路退回 T+3、无重复退（退款幂等键 + 状态机终态保护）。
- 自动续费：3 天提醒 / 7 天宽限降级；资损 **fail-closed（I6：任何不确定一律拦截不发货）**。

### 3.2 平台封禁（反爬 / 反自动化，R-类）
- 适配器降级链（`domParseSuccessRate` 跌落 >20%/5min → 降级）、单平台熔断退避（连续失败 → 退避冷却）必测（LLD-平台适配器 §生命周期）。
- Cookie 健康探活、速率限制、人为节奏随机化（避免固定间隔触发风控）。
- Mock 适配器覆盖 正常 / 限流 / 登录过期 / 结构变更 四类；真实平台变体（反爬升级）登记为「Mock 无法覆盖」，需 periodic 人工抽检（显式缺口，见 §8 G3）。

### 3.3 并发与幂等
- 投递幂等四元组 `(user_id, platform_id, job_id, apply_date)` 唯一（重复投递 → `409 DUPLICATE_REQUEST`）。
- 简历并发编辑 LWW 乐观锁（§3.2.3）；本机 Agent 多设备调度冲突消解（§27.1 / §30.4 四元组幂等收敛）。
- 请求级幂等 UUID（前端生成）+ 业务幂等四元组双保险。

### 3.4 状态机
- 投递 10 态（§3.4）：允许转移矩阵 + 无回退边 + 跨阶段直达终态；`offer` 必到 `closed`。
- 面试会话 7 态（§6.16 / G7）：无回退边 + 断点续聊 + 单轮 30min 超时。

### 3.5 数据安全与隐私（部分延后）
- 加密信封版本化 + 泄露全量吊销 RTO≤4h（LLD-密钥工程）；差分隐私 k=50 cell suppression + Laplace/Gaussian（LLD-分析报表与隐私）。
- **PIPL 自动化决策(§24) / DSAR / 威胁模型：延后至法务协同，本计划不声称覆盖**，登记待测（§8 G1）。

## 4. 端到端场景

- **E2E-1 投递主链路**：注册/登录(A01/A02) → 创建简历(A04) → 设策略(A12/A13) → 岗位浏览(A07) + 匹配度 → 半自动批量确认(A09，用户显式确认) → 适配器执行采集回写 → 投递 10 态推进 → HR 查看检测 → 通知(A22 / ws A23) → 日报(A24)。
- **E2E-2 面试模拟**：创建会话(A17) → 逐题作答(A18，文本/语音 ASR 降级链) → 评估报告(A19) → 申诉/重跑入口。
- **E2E-3 支付**：下单(A20) → 回调(A21) → 对账 → 权益生效(A03)。
- 每条 E2E 标注必过断言与 Mock 边界（真实平台不触）。

## 5. 可观测性与回归

- 埋点（§27.4，低优先待数据）登记；关键路径日志/追踪（`event-envelope.traceId`）串联。
- 回归套件绑定各模块 LLD 待决项（如解析 `accuracy[H]` / 面试 `rubric` 第 5 维 `[T2]` / 加权权重 `[T3]`），待测项标 `[Hypothesis]` / `[待拍板]`，**不伪装通过**。

## 6. 性能与容量基线

- 单用户自用 / 极早期小规模；500 DAU 为演进触发线；实例池 ≤3 为单 Agent 进程约束（非全局上限）。
- 适配器并发采集受平台速率限制；压测断言不破限流、不触风控。

## 7. 验收标准映射

- 直接映射 **PRD §11 验收标准** 逐条；本计划每条用例标注对应 PRD / HLD / LLD 锚点。
- 发布门禁（§28 N4/N6/N7）：**契约全绿 + 集成必过项 + 高危专项（资损/封禁/并发）全绿** 方可发布。

## 8. 缺口与待决（显式登记，非静默）

- **G1 [延后-法务]**：PIPL 自动化决策(§24) / DSAR 全流程 / 威胁模型——不在本计划覆盖，待法务协同后补专项测试。
- **G2 [待定]**：无障碍（§19）——待定，不纳入本轮。
- **G3 [Mock 局限]**：真实平台反爬变体无法被 Mock 适配器覆盖，需 periodic 人工抽检 + 适配器健康告警兜底。
- **G4 [编码期]**：Pact 消费方契约测试、端到端自动化（受控账号）留编码期嵌入；本计划定义策略与门禁，不阻塞当前 LLD / 契约收口。
