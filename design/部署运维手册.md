# 部署运维手册（Deployment & Operations Runbook）

> 文档版本：2026-08-16 · v1.0 · 依据 HLD v3.31（对齐 PRD v4.5）
> 编制视角：资深架构师 / SRE 运维视角
> 目的：把 HLD 中分散的部署形态、韧性、发布治理、可观测性、事件响应决策收敛为**可执行的操作手册**，作为上线与日常运维的权威依据。本手册与 `测试计划.md`、`HLD-风险登记表-v1.md` 共同构成 P2 交付闭环。

---

## 0. 范围与边界

本手册覆盖：

- 服务端（Java 业务服务 + Python LLM 服务 + 数据层）部署与运维；
- 用户侧**本机 Agent**（桌面守护进程）部署、自更新与本地降级；
- 配置中心、kill switch、可观测性、告警、备份/容灾、发布治理、安全运维、数据迁移、事件响应 SOP。

本手册**不覆盖**（已登记为显性风险接受，见 `HLD-风险登记表-v1.md` R-14）：PIPL 自动化决策明示(§24)、DSAR 全流程、安全威胁模型三块的设计——上线前须补。

## 1. 部署架构总览

### 1.1 拓扑（对齐 §2.5 / 图 2-3 / fig-2-3-deployment.svg）

```
┌──────────────────────────────────────────────────────────────┐
│ 用户侧（每用户 1 节点）                                          │
│  ┌────────────────────────────────────────────────────┐      │
│  │ 本机 Agent（桌面守护进程, systemd/launchd）             │      │
│  │  • 浏览器自动化 Playwright（投递/采集/面试模拟）          │      │
│  │  • Cookie 本地信封加密（不上传/不备份云端, §C.5）        │      │
│  │  • 本地 SQLite（去重键/任务状态/在途进度, §21.3）         │      │
│  │  • 自更新（签名校验→保留上一版→切换, §29.3/§30.7）        │      │
│  └───────────────┬────────────────────────────────────┘      │
│       信令/推送   │   RabbitMQ（异步解耦, ADR-002/004）         │
└──────────────────┼───────────────────────────────────────────┘
                   │  REST /internal/* + 事件（MQ）
┌──────────────────▼───────────────────────────────────────────┐
│ 服务端（独立 VPC, 模块化单体）                                   │
│  ┌──────────────┐   ┌──────────────────┐   ┌──────────────┐  │
│  │ Java 服务      │   │ Python LLM 服务    │   │ 数据层         │  │
│  │ (事务/状态机/ │◄─►│ (LLM 网关, 仅调    │   │ MySQL 主从    │  │
│  │  支付)        │   │  外部模型 API)     │   │ Redis/Rabbit  │  │
│  └──────────────┘   └──────────────────┘   └──────────────┘  │
│  注意：服务端**不部署浏览器沙箱**（原 Docker 方案已废弃, §2.5）    │
└──────────────────────────────────────────────────────────────┘
```

**关键红线（不可违反）**：

- 浏览器自动化（Playwright）**只在本机 Agent 侧**运行，服务端无浏览器算力（对齐 PRD §15.1）；
- Cookie 密文**永不出本机 Agent**（信封加密，不上传、不备份云端，§C.5）；
- 各用户从各自 IP 发起投递，规避集中式合规与反封禁风险；
- 服务端 Java/Python **不共享数据库**（ADR-002 双语言异构约束）。

### 1.2 技术栈（对齐 §2.4 / ADR-002）

| 组件 | 选型 | 部署形态 |
|------|------|---------|
| 业务服务 | Java 17 + Spring Boot 3.x | 单机 systemd 守护 + 健康探针 |
| AI/LLM 服务 | Python 3.x + FastAPI | 同机独立进程，仅 LLM 网关 |
| 消息总线 | RabbitMQ | 服务端内部，解耦服务↔本机 Agent |
| 关系库 | 云 MySQL 主从 | 自动备份，RPO≤30min（ADR-003/015） |
| 缓存/队列 | Redis / RabbitMQ | 服务端内部 |
| 本机 Agent | 桌面守护进程 | 用户机器，自更新 + 本地降级 |

### 1.3 演进路径（§2.5⑤）

先模块化单体跑起来 → 热点（LLM 编排 / 投递执行）按需拆独立服务。拆分须保留 Pact 消费者契约（见 `测试计划.md` §契约测试）。

## 2. 环境分层

| 环境 | 用途 | 数据 | 平台行为仿真度 | 准入 |
|------|------|------|---------------|------|
| dev | 本地开发 | 本地 SQLite + 测试库 | 低（Mock 优先） | 无门禁 |
| staging | 预发回归 | 脱敏快照 + 影子库 | 高（接真平台只读/Mock 录制回放） | CI 全绿 + 契约基线绿 |
| prod | 生产 | 生产库 | 真实 | 发布门禁全过（§28.4） |

**保真度策略（补 R-08 长尾）**：staging 须具备"平台 DOM / 反爬行为"高保真仿真——通过 `设计完备性审查报告.md` 登记的 Mock 录制/回放 fixtures（设计态，编码期落地，见 `测试计划.md` G3）实现，避免"环境偏差大→上线即翻车"。

## 3. 服务端部署

### 3.1 进程守护（ADR-015）

- Java/Python 均以 systemd 守护 + 健康探针（`/healthz`）自动拉起；
- OOM/高水位：暂停新任务入队，执行中任务放行；告警后 5min 自动重启空闲实例；
- 崩溃任务携**幂等键** 15min 内重试，不重复投递（§3.10 / ADR-004）。

### 3.2 数据层

- 云 MySQL 主从，自动备份，RPO≤30min；跨 AZ 部署（§C.D）；
- 故障切换 RTO≤30min；核心无状态服务跨 AZ 冗余；
- 云主机快照备份（系统盘 + 挂载盘）。

### 3.3 网络与安全边界

- 服务端置于独立 VPC，仅暴露必要入口（API 网关 / 信令 WS）；
- 本机 Agent↔服务端信令走 OAuth2 客户端凭证 + 短期 access(15min) + 可轮换 refresh + CRL 吊销 + mTLS（§6.5 P，已闭环 R-13）；
- 外部平台 API 调用**仅源自本机 Agent**（各用户 IP），服务端不做平台登录。

### 3.4 配置中心

- 动态配置（速率/限流/适配器选择器/灰度比例/kill switch）经配置中心下发，支持**热更无需发版**；
- 配置变更经发布门禁（§28.4，涉及投递/限流/配置中心须过灰度 + 自动化回归 + 配置校验）。

## 4. 本机 Agent 部署与自更新

### 4.1 安装与守护

- 桌面守护进程（Windows：系统服务 / 计划任务；macOS：launchd）；
- 后台受限态遵循功耗硬预算（§6.7），避免被 OS 杀进程（缓解 R-11）。

### 4.2 自更新回滚（§29.3 / §30.7，补 R-11 长尾）

更新流程：`下载 → 签名校验 → 保留上一版 → 切换`。

- 启动失败**自动回滚上一版**；
- 连续回滚 N 次失败 → 进**受限安全模式 + 显式报错**（绝不静默）；
- 更新密钥 CRL 吊销；构建隔离防同源 bug。

### 4.3 本地 SQLite 完整性（§21.3，补 R-11 长尾）

- **不备份** Cookie / 在途进度；
- 每次启动 + 每 30min 跑 `PRAGMA integrity_check`；
- WAL + 原子事务；每日轻量快照（结构 + 任务状态 + 去重 key）；
- 损坏 → 进受限安全模式 + 显式弹窗，**绝不静默**；
- 去重丢失时**宁可重登重确认也不自动续投**。

### 4.4 后端宕机本地降级（§C.D，关键韧性）

后端宕机时本机 Agent **纯本地降级**：已确认投递照常执行（本地队列），仅"查看/同步/推送"受损，不卡死、不重复投递；恢复后经信令通道增量重连。

## 5. 可观测性

### 5.1 SLI / SLO（§31.5）

| SLI | SLO | 备注 |
|-----|-----|------|
| API p99 延迟 | 分组件（匹配 p99≤5s） | 接错误预算 |
| API 可用性 | 99.9% | — |
| 错误率 | — | 错误预算耗尽则冻结发布 |
| 队列积压 | — | >100 触发告警（§6.9） |
| Agent 心跳存活率 | 被动心跳 + 服务端探活 probe | 度量用户侧实际可用 |

### 5.2 结构化日志与 trace（补 R-05 长尾）

- 日志字段 schema：必含 `trace_id` / `user_id` / `event_type` / `span` / `ts` / `level`；
- 脱敏强制拦截层（§30.9）：写入经脱敏过滤器（Cookie/token/身份证/手机号正则掩码）；落盘日志定期 PII 扫描告警；本地日志同走过滤器。

### 5.3 合成监控与 deadman 告警（§18.4 / §31.5）

- 关键看板（Agent 在线率、投递成功率）**缺失数据本身作为 P2 告警**，而非默认正常；
- 监控 agent/采集管道失联、指标长期无更新 → 触发"无数据告警"；
- 服务端定时经推送通道向 Agent 发探活 probe，补充被动心跳。

## 6. 告警与 Oncall（§24）

### 6.1 告警路由（§6.9）

Alertmanager 规则示例（阈值来自 HLD）：

- 投递成功率 <90%
- 队列积压 >100
- 浏览器 OOM
- 适配器批量停用
- LLM 全降级
- Agent 心跳存活率跌破阈值

### 6.2 事件分级（§24.1）

| 级别 | 确认 | 止血 | Oncall |
|------|------|------|--------|
| SEV1 致命 | 5min | 15min | 7×24 双备份，指定唯一 IC |
| SEV2 严重 | 15min | 1h | 同上 |
| SEV3 一般 | 30min | 当日 | 工单 P1–P3 |

区分"生产事故 SEV"与"工单 P1–P3"。

### 6.3 kill switch（§24.5）

配置中心下发三类急停：

- 冻结自动更新 + 回滚上一稳定版；
- 一键熔断配置；
- 全局急停投递。

**仅 SEV1 IC + 技术负责人双授权触发**，动作入审计。

### 6.4 状态页（§24.7）

独立状态页 + 应用内横幅；SEV1/2 每 30min 播报；统一由 IC/公关口径发布。

## 7. 容量、压测与混沌（§6.5 G / §31.7 / §23.7）

- 上线前按容量模型 **1.5× 压测**（P99 / 错误率门禁）；压测不过不发布；
- 混沌注入：后端宕 / DB 延迟 / Agent 崩溃 / 网络分区；
- 季度 DR 演练复用压测框架；
- 适配器健康分 = DOM 解析成功率，**失败率>20% 持续 5min 自动降级该平台**（§31.3，补 R-09 SLA 长尾）。

---

## 8. 备份与容灾（§C.D / ADR-003/015）

| 对象 | 策略 | RPO / RTO |
|------|------|-----------|
| 服务端无状态服务 | 跨 AZ 部署 | RTO≤30min |
| 云 MySQL | 异步复制 + 自动备份 | RPO≤30min |
| 云主机 | 快照备份 | — |
| 本机 Agent 本地库 | **不备份 Cookie/在途**；PC 损坏重装后拉非敏感配置 + 用户重登各平台 | — |
| 投递/日报历史 | 服务端持有，可恢复 | — |

**DR 演练**：季度级故障切换演练，验证 RTO≤30min 与本地降级路径。

## 9. 发布治理（§28 / §31.12）

### 9.1 发布门禁（§28.4）

涉及**投递 / 限流 / 配置中心**的变更须过：灰度门禁 + 自动化回归 + 配置校验；动态基线异常自动升 SEV。

### 9.2 灰度自动回滚 guardrail（§31.12）

任一触发即自动回滚上一良好版（与 break-glass 协同）：

- 错误率 >2% 持续 5min
- p99 > 基线 2 倍
- 误投率 >0.1%
- 成本突增 >3 倍
- Agent 崩溃率 >1%

### 9.3 LLM 成本双闸（§28.1）

- 单用户实时速率 + 日预算双限；
- 日耗 70% / 90% 内/外告警，100% 自动降级规则匹配；
- 单会话最大调用轮次；全局成本突增 +300% 告警。

### 9.4 第三方依赖韧性（§31.3）

- 支付状态**双源校验**（轮询 + webhook，超时转"待确认"不重复扣）；
- 推送送达率跌破阈值切备用通道（站内信 / 邮件）；
- 招聘适配器健康分驱动的自动降级（见 §7）。

## 10. 安全运维

- 密钥与凭证工程（§31.7 / `LLD-密钥与凭证工程-模块设计.md`）：定期轮换；泄露全量吊销（CRL）；
- 信令凭证 CRL 吊销时效 + refresh 轮换持续监测（R-13 已缓解项）；
- 脱敏层（§30.9）落地与 PII 扫描告警；
- Cookie 信封加密（§C.5）仅本机，密钥与业务库分离、定期轮换。

## 11. 数据迁移与 Schema 演进（§C / PRD §23.3）

- 持久化表带 `schema_version`；
- 迁移脚本版本化、幂等、可回滚；

## 12. 事件响应 SOP（速查）

| 场景 | 动作 | 引用 |
|------|------|------|
| 适配器批量失效/封号潮 | 触发 §31.3 自动降级单平台；SEV 评估；必要时 kill switch 急停投递 | §7 / §6.3 |
| 支付对账不平 | fail-closed 暂停权益激活并告警（I6）；人工介入对账差异 | §3.10 / §6.1 |
| 本机 Agent 崩溃率>1% | 灰度自动回滚 guardrail 触发回滚；受限安全模式排查 | §9.2 |
| 后端全宕 | 本机 Agent 纯本地降级继续投递；恢复增量重连 | §4.4 / §8 |
| 信令凭证泄露 | CRL 吊销 + refresh 全量轮换；监测异常 | §10 / R-13 |
| LLM 成本突增+300% | 成本双闸降至规则匹配；告警 + 排查 | §9.3 |
